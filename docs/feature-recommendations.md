# Рекомендації щодо розвитку платформи

> Результат аналізу функціоналу платформи (червень 2026). Збережено, щоб
> повернутися згодом. Статус кожної фічі позначено: ✅ зроблено · ⬜ заплановано.

## Що платформа вже робить добре (фундамент)

Це база, яка робить багато нових фіч дешевими:

- **Детермінований trace** — алгоритм проганяється раз → незмінні кадри `Frame`,
  UI лише рухає курсор. Будь-який стан плеєра однозначний і серіалізовний.
- **`registry.ts` як єдине джерело правди** — порядок алгоритмів кодує
  педагогічну послідовність; є `complexity`, `family`, `category`, `taglines`.
- **Спільний playback-kit + doc-codec + hash-роут** — один шар обслуговує всі
  екрани; вхід шариться через `?g=`.
- **Двоступеневі кадри «інтрига → розв'язок»** (binary decision, linear match,
  Kruskal accepted/rejected) — спроєктовані під активне навчання.

Три потужні фічі поки **замкнені лише в Краскалі**: бенчмарк (lib core / Web
Worker / hook / Recharts), CompareView (два алгоритми пліч-о-пліч), DecisionTable.

## 🟢 Швидкі перемоги (низька ціна / висока віддача)

1. ✅ **Матриця складності всіх 20** (`#compare`) — *реалізовано*. Read-only
   таблиця над `registry` із сортуванням за зростанням, кольоровим градієнтом
   класу й позначкою деградації. Заклала реєстр службових сторінок `PAGE_IDS`
   у роутері — фундамент для пунктів 4 і family-overview нижче.

2. ⬜ **Гарячі клавіші плеєра** — один хук `usePlayerHotkeys` у `PlayerShell`
   (Space / ←→ / Home·End / 1·2·3) поверх наявних reducer-екшенів. `PlayerShell`
   обгортає всі плеєри → одна зміна = глобальне покриття. Guard на текстові поля.

3. ⬜ **Картка передумов і складності в шапці розділу + детектор порушеної
   передумови** — опційні поля в `Algorithm`; чек-лист ✓/✗ оживляється проти
   входу (`isSorted` для пошуків, `analyzeGraph.isConnected` для графів). Ловить
   помилку «двійковий працює всюди» в момент дії; не блокує, а повчально попереджає.

4. ⬜ **Навчальні шляхи + місточки «Звідки/Куди»** — ОДИН декларативний масив
   `bridges` у `registry`, що живить три вставки: секцію «Шляхи» на Home, футер
   «← попередній / Наступний →» у Shell, `BridgeNav` у Learn. Формалізує те, що
   вже закладено в порядок алгоритмів і taglines (linear→binary = «винагорода за
   сортування», naive→KMP = «пам'ять про себе»).

5. ⬜ **Текстовий пошук на Home + серіалізація фільтрів у хеш**
   (`#?family=…&class=…`) — `HomeView` уже має всю логіку фільтрів.

6. ⬜ **Друк / PDF конспекту Learn** — `@media print` CSS + `window.print()`,
   нуль залежностей.

## 🔵 Великі ставки (трансформаційні)

7. ⬜ **Дип-лінк на конкретний КРОК плеєра** (`?g=…&step=N&mode=X`) + кнопка
   «Поділитися кроком». Перетворює ефемерну сесію на цитоване посилання: «Краскал,
   крок 7, режим DSU». *Ризик: `mode` — локальний `useState` у ~14 не-графових
   плеєрах; потрібен спільний `use-playback-deeplink`.* Комбінується з embed.

8. ⬜ **Режим «Вгадай рішення» (predict-before-reveal)** — на кадрі-«інтризі»
   автопрогравання стоп, над панеллю 2-3 кнопки-варіанти, після кліку розкриття
   з ✓/✗. Спільний `questionForFrame(frame)` з дефолтом «пропуск». **Найсильніший
   педагогічний важіль** — пасивний перегляд стає активним рішенням.

9. ⬜ **MCQ-чекпойнти в Learn** через нову `quiz-*.svg` фігуру в `figureForSrc`
   (декларація в `learn-quiz.<id>.ts`, двомовно). Миттєвий фідбек + адресне
   пояснення *чому* невірно — прицільно по типових хибних уявленнях.

10. ⬜ **Узагальнення бенчмарку в registry-driven kit** (`Benchmarkable`
    дескриптор + спільний worker + generic Recharts-view). Найбільший структурний
    розрив («бенчмарк лише в Краскалі»). *Критично: run-fn сортувань мусить
    клонувати масив — сорти мутують in-place.* На цьому будуються:
    - **Режим «операції vs n»** (тумблер ms ⇄ операції) на вже unit-тестованих
      лічильниках — ізолює алгоритмічну роботу від JS/GC-шуму;
    - **Теоретична крива поверх емпіричної** (`lib/complexityBounds.ts`) —
      перетворює графік на інструмент валідації складності.

11. ⬜ **Маркери фаз на таймлайні** (семантичний скрабер) — засічки там, де
    `frame.phase` змінюється (перехід LPS→пошук у KMP, межі проходів, рекурсивні
    занурення), клік → seek. Плюс рядок-діф «що змінилось між кадрами».

12. ⬜ **PWA (офлайн + інсталяція)** через `vite-plugin-pwa` — уся обчислювалка
    клієнтська, markdown інлайниться на build-time → майже офлайн-готово.
    *Scope/start_url мусять враховувати `base: '/kruskal-mst-visualizer/'`.*

13. ⬜ **Embed-режим для викладачів** (`?embed=1`) + «Скопіювати код для вставки»
    (`<iframe>`) — платформа стає вбудовуваним об'єктом у Moodle/слайди.

14. ⬜ **Контрактні smoke-тести вкладок для всіх алгоритмів** (параметризований
    Vitest+RTL із `registry`). Зараз перевага lib-тестів проти UI: одна регресія
    в `PlayerShell` тихо ламає всі екрани.

## ⛔ Що НЕ варто робити (свідомо)

- **Акаунти / бекенд / хмарна синхронізація / аналітика / freemium** — все
  client-side, без сервера; поза скоупом.
- **Ширша a11y / axe-core** — поза скоупом проєкту (виняток reduced-motion, уже є).
- **Третя мова** — типізована парність UA/EN навмисна; велика інвазія без запиту.
- **Експорт GIF з новим енкодером** — порушує «не додавай залежності без потреби»;
  KaTeX/Shiki/React Flow погано серіалізуються.
- **Аудіо-нарація (TTS), кастомний слайдер швидкості, хореографовані анімації** —
  не вписуються в trace-модель незмінних кадрів.
- **Гейміфікація заради балів (leaderboard, daily)** — ризик «балів заради балів»;
  локальний прогрес можливий, але вторинний.

## Наскрізні теми

1. **Шаринг і відтворюваність через хеш** — серіалізувати не лише вхід, а й
   позицію в плеєрі, фасети каталогу, embed-прапор. Одна архітектурна лінія.
2. **Активне навчання поверх двоступеневих кадрів** — predict-режим, MCQ,
   детектор передумов б'ють по хибних уявленнях майже без зміни ядра.
3. **`registry` як read-model для крос-алгоритмової навігації** — матриця, шляхи,
   місточки, дерево вибору — все декларативно над одним джерелом.
4. **Узагальнення kruskal-only інфри** — бенчмарк і CompareView мають чистий
   патерн, бракує лише абстракції (`Benchmarkable`, `DualTraceShell`).
5. **Зрілість без бекенду** — PWA, embed, тестова надійність майже безкоштовні
   на наявній client-side архітектурі.
