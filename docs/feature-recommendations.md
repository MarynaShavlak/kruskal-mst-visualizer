## Що платформа вже робить добре (фундамент)

Це база, яка робить багато нових фіч дешевими:

- **Детермінований trace** — алгоритм проганяється раз → незмінні кадри `Frame`,
  UI лише рухає курсор. Будь-який стан плеєра однозначний і серіалізовний.
- **`registry.ts` як єдине джерело правди** — порядок алгоритмів кодує
  педагогічну послідовність; є `complexity`, `family`, `category`, `taglines`.
- **Спільний playback-kit + doc-codec + hash-роут** — один шар обслуговує всі
  екрани; вхід шариться через `?g=`.
- **Двоступеневі кадри «інтрига → розв'язок»** (binary decision, linear match,
  Kruskal accepted/rejected) — спроєктовані під активне навчання.

Три потужні фічі поки **замкнені лише в Краскалі**: бенчмарк (lib core / Web
Worker / hook / Recharts), CompareView (два алгоритми пліч-о-пліч), DecisionTable.

## ⛔ Що НЕ варто робити (свідомо)

- **Акаунти / бекенд / хмарна синхронізація / аналітика / freemium** — все
  client-side, без сервера; поза скоупом.
- **Ширша a11y / axe-core** — поза скоупом проєкту (виняток reduced-motion, уже є).
- **Третя мова** — типізована парність UA/EN навмисна; велика інвазія без запиту.
- **Експорт GIF з новим енкодером** — порушує «не додавай залежності без потреби»;
  KaTeX/Shiki/React Flow погано серіалізуються.
- **Аудіо-нарація (TTS), кастомний слайдер швидкості, хореографовані анімації** —
  не вписуються в trace-модель незмінних кадрів.
- **Гейміфікація заради балів (leaderboard, daily)** — ризик «балів заради балів»;
  локальний прогрес можливий, але вторинний.

## Наскрізні теми

1. **Шаринг і відтворюваність через хеш** — серіалізувати не лише вхід, а й
   позицію в плеєрі, фасети каталогу, embed-прапор. Одна архітектурна лінія.
2. **Активне навчання поверх двоступеневих кадрів** — predict-режим, MCQ,
   детектор передумов б'ють по хибних уявленнях майже без зміни ядра.
3. **`registry` як read-model для крос-алгоритмової навігації** — матриця, шляхи,
   місточки, дерево вибору — все декларативно над одним джерелом.
4. **Узагальнення kruskal-only інфри** — бенчмарк і CompareView мають чистий
   патерн, бракує лише абстракції (`Benchmarkable`, `DualTraceShell`).
5. **Зрілість без бекенду** — PWA, embed, тестова надійність майже безкоштовні
   на наявній client-side архітектурі.
