# Двійкове дерево пошуку

Ти вже вмієш **обходити** дерево. Тепер надамо дереву одне-єдине **правило порядку** — і воно перетвориться на потужну структуру для швидкого пошуку, вставки та видалення. Це **двійкове дерево пошуку** (ДДП, англ. *binary search tree*): для кожного вузла всі ключі в **лівому** піддереві **менші** за нього, а всі ключі в **правому** — **більші**.

## 1. Правило порядку

Дерево двійкового пошуку — це двійкове дерево з інваріантом: для **будь-якого** вузла зі значенням `x`

- усе, що ліворуч від `x`, **менше** за `x`;
- усе, що праворуч від `x`, **більше** за `x`.

Правило діє **рекурсивно** — не лише для прямих дітей, а для цілих піддерев. Саме воно перетворює пошук на низку рішень «ліворуч чи праворуч?» замість перегляду всіх вузлів.

![Дерево двійкового пошуку — правило порядку](docs/images/bst_anatomy.png)

Ми розглядаємо ДДП як **множину унікальних ключів**: повторна вставка наявного ключа нічого не змінює.

## 2. Пошук: спуск за правилом

Шукаємо ключ `k`. Починаємо з кореня і на кожному вузлі порівнюємо:

- `k == вузол` → **знайдено**;
- `k < вузол` → йдемо **ліворуч** (праворуч усе завідомо більше — там `k` бути не може);
- `k > вузол` → йдемо **праворуч**.

Дійшли до порожнього місця — ключа немає. Кожне порівняння **відкидає ціле піддерево**, тож шлях пошуку дорівнює лише **глибині** дерева.

```python {4-7}
def search(root, key):
    if root is None:
        return None             # порожньо → немає ключа
    if key == root.val:
        return root             # знайдено
    if key < root.val:
        return search(root.left, key)   # менше → ліворуч
    return search(root.right, key)      # більше → праворуч
```

Погортай усю історію нижче: побудова дерева, пошук ключа `4` і видалення вузла `7`. Стеж за **шляхом порівнянь** (🔵) і вузлом, який зважуємо **зараз** (🟡).

![Покрокова історія: побудова, пошук, видалення](docs/images/bst_walk.png)

## 3. Вставка: знайти порожнє місце

Вставка — це той самий спуск, що й пошук, але «до кінця»: рухаємось ліворуч/праворуч, доки не впремося в **порожнє посилання**. Саме туди й підвішуємо новий вузол-лист.

```python {2-3}
def insert(root, key):
    if root is None:
        return Node(key)        # порожнє місце → новий вузол
    if key < root.val:
        root.left = insert(root.left, key)    # менше → ліворуч
    elif key > root.val:
        root.right = insert(root.right, key)  # більше → праворуч
    # key == root.val → уже є, пропускаємо
    return root
```

**Порядок вставок вирішує форму дерева.** Ключі «від середини» дають збалансоване дерево; уже впорядкований вхід (1, 2, 3, …) — вироджений «ланцюг».

## 4. Видалення: три випадки

Видалення складніше: прибравши вузол, треба **зберегти інваріант**. Спершу знаходимо вузол тим самим спуском, а далі — один із трьох випадків:

1. **Лист** (немає дітей) — просто прибираємо.
2. **Один нащадок** — ставимо цього нащадка на місце вузла.
3. **Два нащадки** — знаходимо **наступника**: найменший ключ у **правому** піддереві (спуск ліворуч до упору). Копіюємо його значення у вузол, а сам наступник (він має щонайбільше одного нащадка) прибираємо за випадком 1 або 2.

Чому саме наступник? Він більший за все ліве піддерево і менший за решту правого — тобто ідеально «затикає дірку», не порушивши правила порядку.

## 5. Форма вирішує все: O(log n) проти O(n)

Кожна операція коштує рівно стільки порівнянь, яка **висота** дерева. А висота залежить від форми:

- **Збалансоване** дерево з `n` вузлів має висоту ≈ `log₂ n` → операції **O(log n)**;
- **Вироджене** (ланцюг з упорядкованого входу) має висоту `n − 1` → операції **O(n)**, не краще за звичайний список.

![Збалансоване дерево проти виродженого ланцюга](docs/images/bst_shape.png)

Це головний урок ДДП: сама ідея логарифмічна, але **гарантії** її немає — форму псує невдалий порядок вставок. Саме тому існують самобалансувальні дерева (AVL, червоно-чорні), що тримають висоту `O(log n)` попри все.

## 6. Нагорода: центровий обхід = відсортовано

Пригадай **центровий** обхід (ліве → корінь → праве). Через правило порядку він видає ключі **за зростанням**:

![Центровий обхід ДДП дає відсортовану послідовність](docs/images/bst_inorder.png)

Для нашого дерева це `2, 3, 4, 5, 6, 7, 8`. Тобто ДДП «безкоштовно» тримає дані відсортованими, а на відсортованих даних працює **двійковий пошук** — коло замкнулося.

## 7. Перевір себе

![Міні-квіз: випадок видалення](docs/images/bst_quiz.png)

**Куди далі.** Дерево пошуку будувало відповідь із піддерев — та сама думка «знизу вгору», що й у зворотному обході. Наступний крок — окрема парадигма, **динамічне програмування**, де оптимум складають із розв'язків менших підзадач; найчистіший перший приклад — **рюкзак 0/1**.
