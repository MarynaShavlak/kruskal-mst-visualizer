# Наївний алгоритм пошуку в рядках (Naive String Search): покроковий розбір

**Наївний пошук у рядках** — найпростіший алгоритм пошуку підрядка: щоб знайти **шаблон** `pattern` у **тексті** `main_string`, ми **ковзаємо** шаблоном уздовж тексту й на кожному вирівнюванні (зміщенні `i`) порівнюємо символи зліва направо. Щойно всі символи шаблону збіглися — повертаємо позицію `i`; на першій же розбіжності зсуваємо шаблон **на одну позицію вправо** й починаємо звірку заново з `j = 0`. Якщо жодне вирівнювання не підійшло — повертаємо `-1`. Жодної передобробки: метод працює на будь-якому рядку (текст, ДНК, лог) і не потребує сортування чи інших передумов.

Це **перший рядковий алгоритм** у серії — нова предметна область: дані тут не числовий масив, а **послідовності символів** (текст + шаблон), а операція — посимвольна **рівність** (`==`). За духом це прямий аналог [лінійного пошуку](https://github.com/MarynaShavlak/algo-linear-search) для масивів: брутфорс, нуль передобробки. «Ціна» алгоритму — **кількість посимвольних порівнянь**; визначальна його риса — **марна робота**: після часткового збігу й розбіжності наївний метод викидає все й зсувається лише на 1, **повторно** порівнюючи вже звірені символи. Саме це й прибирають смартніші наступники — KMP, Боєра-Мура, Рабіна-Карпа.

## 1. Інтуїція: шукаємо слово вручну

Уявіть, що шукаєте слово в тексті «вручну»: ведете **пальцем** по рядку й звіряєте літера за літерою. Не збіглося на якійсь літері — зсуваєте слово на **одну позицію** вправо й починаєте звірку знову з початку. Саме так працює наївний пошук: шаблон ковзає вздовж тексту, а на кожному вирівнюванні порівнюються символи зліва направо.

Спершу ставимо шаблон на початок тексту й починаємо звіряти символи зліва направо:

![Текст HELLO WORLD і шаблон WORLD на старті](docs/images/intuition_setup.png)

![Шукаємо WORLD у HELLO WORLD: звіряємо літера за літерою](docs/images/intuition_slide.png)

Поточну пару символів, що порівнюються, з'єднує **місток** «текст ↔ шаблон». Збіг символу позначаємо **зеленим**, розбіжність — **червоним**. Не збіглося — зсуваємось на 1 і пробуємо знову; так доходимо до позиції, де збіглося все слово (тут — позиція 6).

## 2. Ідея методу: ковзаємо шаблоном

Основний принцип: порівнюємо кожен символ головного рядка з першим символом шаблону; якщо вони збігаються — порівнюємо наступні символи до кінця шаблону. Кроки для кожного символу головного рядка:

1. Порівняйте цей символ і наступні символи з символами шаблону.
2. Якщо **всі** символи шаблону збіглися — підрядок знайдено.
3. Якщо хоч один символ не збігся — переходимо до **наступного** символу головного рядка (зсув на 1).

Шаблон ставимо під текст на зміщенні `i`; символ шаблону `j` опиняється під символом тексту `i + j`:

![Шаблон ABABCABAB на зміщенні i = 0](docs/images/intro_align_i0.png)

## 3. Два індекси: `i` (вирівнювання) і `j` (позиція в шаблоні)

Роботу методу описують **два** індекси:

- зовнішній **`i`** — **зміщення** вирівнювання шаблону вздовж тексту (зовнішній цикл `for` — «яке вирівнювання»);
- внутрішній **`j`** — **позиція** всередині шаблону (внутрішній цикл `while j < M` — «посимвольне порівняння на цьому вирівнюванні»).

На кожному вирівнюванні `i` внутрішній цикл біжить `j = 0, 1, 2, …` і порівнює `main_string[i + j]` з `pattern[j]`, доки символи збігаються. На розбіжності — `break`, і зовнішній цикл зсуває шаблон (`i + 1`), починаючи звірку знову з `j = 0`.

## 4. Базова реалізація

Ось базова реалізація — її ми й розбираємо рядок за рядком:

```python
def naive_search(main_string, pattern):
    M = len(pattern)
    N = len(main_string)

    # Перебір по символах головного рядка
    for i in range(N - M + 1):
        j = 0

        # Перебір по символах підрядка
        while j < M:
            if main_string[i + j] != pattern[j]:
                break
            j += 1

        # Якщо значення j дорівнює довжині підрядка, то підрядок знайдено
        if j == M:
            return i

    return -1

main_string = "ABABDABACDABABCABAB"
pattern = "ABABCABAB"
position = naive_search(main_string, pattern)

if position != -1:
    print(f"Підрядок знайдено на позиції {position}")
else:
    print("Підрядок не знайдено в головному рядку.")
```

Що тут що:

- `for i in range(N - M + 1)` — **зовнішній цикл**: перебираємо всі зміщення вирівнювання `0, 1, …, N-M` (далі шаблон уже не влізе в текст);
- `while j < M` — **внутрішній цикл**: посимвольно звіряємо шаблон зліва направо;
- `if main_string[i + j] != pattern[j]: break` — **розбіжність**: символи різні → перериваємо звірку й зсуваємо шаблон на 1;
- `j += 1` — **збіг символу**: переходимо до наступного символу шаблону;
- `if j == M: return i` — **повний збіг**: усі `M` символів збіглися → повертаємо зміщення `i`;
- `return -1` — жодне вирівнювання не підійшло, шаблона **немає** в тексті.

Навчальна версія `naive_search_steps` повторює цей код **дія в дію**, але після кожного порівняння записує знімок стану й лічильники (порівнянь, вирівнювань, зсувів) — саме з цих знімків зібрані всі картинки нижче.

Запуск драйвера друкує рівно:

```text
Підрядок знайдено на позиції 10
```

## 5. Як читати кадри

- верхній рядок — **текст** (усі `N` символів), нижній — **шаблон**, зсунутий на зміщення `i`;
- 🟢 **зелена комірка** — символ шаблону **збігся** з символом тексту;
- 🔴 **червона комірка** — символ **розбіжності** (саме тут шаблон зривається й зсувається на 1);
- 🔵 **блакитна комірка** — символ у поточному **вікні**, який ще **не порівнювали**;
- ⬜ **нейтральна / 🩶 затемнена** — символ тексту поза вікном (попереду / уже пройдено);
- 🟠 **бурштинова комірка** — символ, який порівнюють **повторно** після зсуву (марна робота);
- угорі — **бейдж «шукаємо шаблон: …»**, під кадром — **вердикт** і **лічильники** (порівнянь · вирівнювань · зсувів).

## 6. Трасування: вирівнювання за вирівнюванням

Шукаємо `ABABCABAB` у `ABABDABACDABABCABAB` (`N = 19`, `M = 9`). Перше вирівнювання `i = 0` дає **частковий збіг**: префікс `ABAB` збігається (чотири зелені), але на `j = 4` розбіжність — `D ≠ C`:

![Вирівнювання i = 0: ABAB збіглося, потім D ≠ C](docs/images/intro_mismatch_i0.png)

Розбіжність → зсуваємо шаблон на 1 (`i = 1`) і починаємо звірку знову з `j = 0`. Так іде вирівнювання за вирівнюванням. Перші п'ять порівнянь на `i = 0` детально:

| `j` | `text[i+j]` | `pattern[j]` | результат |
|---|---|---|---|
| 0 | `A` (text[0]) | `A` | збіг → `j += 1` |
| 1 | `B` (text[1]) | `B` | збіг → `j += 1` |
| 2 | `A` (text[2]) | `A` | збіг → `j += 1` |
| 3 | `B` (text[3]) | `B` | збіг → `j += 1` |
| 4 | `D` (text[4]) | `C` | **розбіжність** → `break`, зсув |

Підсумок по всіх 11 вирівняннях — видно, скільки порівнянь «з'їдає» кожне з них:

```text
Підсумок по вирівняннях (i → результат, у дужках — порівнянь):
  i= 0: збіглося 4, розбіжність на j=4 (D≠C) → зсув  (5)
  i= 1: збіглося 0, розбіжність на j=0 (B≠A) → зсув  (1)
  i= 2: збіглося 2, розбіжність на j=2 (D≠A) → зсув  (3)
  i= 3: збіглося 0, розбіжність на j=0 (B≠A) → зсув  (1)
  i= 4: збіглося 0, розбіжність на j=0 (D≠A) → зсув  (1)
  i= 5: збіглося 3, розбіжність на j=3 (C≠B) → зсув  (4)
  i= 6: збіглося 0, розбіжність на j=0 (B≠A) → зсув  (1)
  i= 7: збіглося 1, розбіжність на j=1 (C≠B) → зсув  (2)
  i= 8: збіглося 0, розбіжність на j=0 (C≠A) → зсув  (1)
  i= 9: збіглося 0, розбіжність на j=0 (D≠A) → зсув  (1)
  i=10: повний збіг шаблону → позиція 10  (9)
```

Зверніть увагу на вирівнювання `i = 0`, `i = 2`, `i = 5`, `i = 7` — на них шаблон збігається **частково** (повторюваний префікс `ABAB`), і саме на них наївний метод марнує найбільше роботи, але все одно зсувається лише на 1. Усі вирівнювання, що ковзають праворуч на 1 щорядка, видно одразу — це «драбинка» ковзання:

![Драбинка ковзання: усі вирівнювання одне під одним](docs/images/intro_evolution.png)

## 7. Сітка вирівнювань: погляд «з висоти»

Якщо подивитися на всю роботу «з висоти» — матриця, де рядки це вирівнювання `i = 0..N-M`, а стовпці це позиції тексту `0..N-1`. Кожна клітинка зафарбована: 🟢 збіг, 🔴 розбіжність, 🔵 у вікні, але не порівнювали (зірвалися раніше). Видно, що один і той самий стовпець тексту порівнюють на **кількох** вирівняннях — це і є надлишкова робота:

![Сітка вирівнювань: уся робота наївного пошуку](docs/images/intro_grid.png)

Усього **29** посимвольних порівнянь — і це при тому, що позицій тексту лише **19**. Наївний метод повертається до вже переглянутих символів знову й знову.

![Повний збіг на позиції 10](docs/images/intro_match.png)

## 9. Марна робота: повторні порівняння й місток до KMP

Це **ядро уроку**. Подивіться на вирівнювання `i = 0`: шаблон збіг префікс `ABAB` (позиції тексту 0–3), а тоді спіткнувся на `D ≠ C`. Що робить наївний метод? Викидає **весь** цей частковий збіг і зсуває шаблон лише на **одну** позицію — на `i = 1`. І тепер символи тексту `1, 2, 3` він порівнює **заново** (бурштинові), хоча вже бачив їх мить тому:

![Марна робота: повторні порівняння після зсуву](docs/images/wasted_work.png)

Саме ця надлишковість і робить наївний метод повільним на «структурованих» текстах. Смартніші алгоритми (KMP, Боєра-Мура) використовують інформацію про вже звірений префікс, щоб **не** порівнювати ці символи вдруге — і зсуваються одразу на кілька позицій. Наївний метод цього не вміє: він починає кожне вирівнювання «з чистого аркуша».

## 10. (Не)ефективність: випадок «не знайдено»

Коли шаблона в тексті немає, наївний метод чесно перебирає **всі** вирівнювання до кінця й повертає `-1` (гілка `else` друкує відповідний рядок). Текст `ABABABABAB`, шаблон `ABABB` — повторюваний префікс `ABAB` дає частковий збіг на кожному другому вирівнюванні, та все марно:

![Сітка вирівнювань для випадку «не знайдено»](docs/images/not_found_grid.png)

```text
Випадок «не знайдено»: текст «ABABABABAB», шаблон «ABABB»
Підрядок не знайдено в головному рядку.
  → порівнянь: 18, вирівнювань: 6, зсувів: 6
```

## 11. Найгірший випадок і складність

Скільки порівнянь робить наївний метод? У **найкращому** випадку (розбіжність на першому ж символі кожного вирівнювання) — приблизно `N-M+1` (по одному порівнянню на вирівнювання). У **найгіршому** — патологічний антиприклад: текст `AAAAAAAAAA`, шаблон `AAAAB`. На **кожному** вирівнюванні збігається весь префікс `AAAA` (чотири зелені), і лише останній символ `B` дає розбіжність — тобто майже `M` порівнянь на кожне з `N-M+1` вирівнювань:

![Найгірший випадок AAAAAAAAAA / AAAAB: вибух порівнянь](docs/images/worst_case.png)

```text
Найгірший випадок: текст «AAAAAAAAAA», шаблон «AAAAB»
  → порівнянь: 30 = (N-M+1)·M = 6·5  (майже m порівнянь на кожне вирівнювання)
Найкращий випадок (розбіжність на першому символі щоразу): ≈ N-M+1 = 11
```

Звідси складність наївного пошуку — $O(n \cdot m)$ (де $n$ — довжина тексту, $m$ — довжина шаблону). Коли довжина шаблону $m$ наближається до довжини тексту $n$, це вироджується в $O(n^2)$ — неефективно для довгих рядків:

![Криві складності: n / n·m / n²](docs/images/complexity.png)

## 12. Варіанти: усі входження `naive_search_all`

Базовий `naive_search` повертає **перше** входження й одразу спиняється. Якщо потрібні **всі** входження (зокрема такі, що перекриваються), доводиться продовжити ковзання до кінця тексту — це робить `naive_search_all`. На `ABABAB` шаблон `AB` трапляється тричі:

![Усі входження AB: позиції 0, 2, 4](docs/images/all_matches.png)

```text
Множинні входження: naive_search повертає ПЕРШЕ, naive_search_all — усі
  текст «ABABAB», шаблон «AB»
  перше входження (naive_search): позиція 0
  усі входження (naive_search_all): [0, 2, 4]
```

## 13. Pythonic-варіант через зрізи

Ту саму ідею можна записати ідіоматично — через **зрізи** Python: замість ручного внутрішнього циклу беремо зріз тексту завдовжки з шаблон і порівнюємо його з шаблоном одним оператором `==`:

```python
def naive_search_slices(main_string, pattern):
    M = len(pattern)
    N = len(main_string)
    for i in range(N - M + 1):
        if main_string[i:i + M] == pattern:
            return i
    return -1
```

Це **той самий** набір зміщень `i` і **той самий** результат, що й у базовій версії — лише посимвольне порівняння сховане всередині оператора `==` рядків (його робить сам Python). Для підрахунку «ціни» (посимвольних порівнянь) користуйтесь `count_comparisons` над базовою версією — на канонічному прикладі це **29**.

## 15. Покрокове виконання коду: панелі «код ↔ дані»

Приклади вище показували *результат* кожного кроку. Тут — **сам код у дії**: ліворуч фрагмент алгоритму з **підсвіченими активними рядками**, праворуч — вирівнювання «текст ↔ шаблон» саме в цей момент. **Колір рядка коду кодує, що відбувається:** 🟡 рядок виконується зараз (цикл / перевірка `main_string[i+j] != pattern[j]` / `j += 1`), 🟢 `j == M` → `return i` (знайдено), 🔴 розбіжність (`break`, зсув) або вичерпання (`return -1`).

## 17. Складність і властивості

Скільки роботи робить наївний пошук, залежить від того, наскільки добре шаблон «частково збігається» з текстом:

| Випадок | Порівняння | Коли трапляється |
|---|---|---|
| **Найкращий** | $O(n)$, $\approx n - m + 1$ | розбіжність на першому символі кожного вирівнювання |
| **Типовий** | $O(n \cdot m)$ | звичайний текст |
| **Найгірший** | $O(n \cdot m)$, при $m \approx n$ → $O(n^2)$ | шаблон майже збігається на кожному вирівнюванні (`AAAA…` / `AAA…B`) |

Інші властивості:

- **Не змінює рядки:** метод лише *читає* символи; додаткова пам'ять — $O(1)$.
- **Без передумов:** працює на будь-якому тексті — на відміну від двійкового пошуку в масивах, тут **нічого не треба сортувати** чи впорядковувати.
- **Метрика — кількість посимвольних порівнянь** (`main_string[i+j] == pattern[j]`); плюс лічильники вирівнювань і зсувів.
- **Перше входження при дублікатах:** `naive_search` повертає найлівіше входження; усі дає `naive_search_all`.
- **Чутливість до регістру:** `==` розрізняє `A` та `a` — пошук чутливий до регістру.

## 18. Обмеження й крайові випадки

Головне обмеження — **марна робота**: наївний метод не пам'ятає вже звірених символів і після часткового збігу зсувається лише на 1, порівнюючи їх заново. Для **довгих** текстів зі структурою це дорого. Чесно про крайові випадки (метод поводиться з ними коректно):

| Крайовий випадок | Поведінка |
|---|---|
| **Порожній шаблон** (`M = 0`) | `range(N+1)`, внутрішній `while` не виконується, `j == M == 0` одразу → повертає `0` |
| **Шаблон довший за текст** (`M > N`) | `N - M + 1 ≤ 0` → `range` порожній → одразу `-1` |
| **Шаблон == текст** | повний збіг на `i = 0` → `0` |
| **Шаблон з одного символу** | звичайний пошук одного символу |
| **Різний регістр** | `A` ≠ `a` → пошук їх не сплутає |

## 19. Де це доречно

Попри неефективність у найгіршому випадку, наївний метод цілком придатний там, де його простота окупається:

- **Короткі тексти** або **рідкісні збіги** — мала кількість вирівнювань, різниця з KMP непомітна.
- **Базовий «Знайти»** у текстових редакторах і редагувальних полях — пошук слова в невеликому документі.
- **Будь-який алфавіт без передобробки** — текст, ДНК, бінарні дані: нічого не треба індексувати чи сортувати.
- **Простота й прозорість** — еталон коректності, з яким звіряють складніші алгоритми.

## 20. Місце в серії: перший крок до рядкового пошуку

Це **перший рядковий алгоритм** у серії — він **відкриває підсерію пошуку в рядках**. До нього були алгоритми сортування й пошуку в **масивах** чисел; тепер предметна область — **рядки символів**. Зв'язок прямий: наївний пошук для рядків — це те саме, що **лінійний пошук** для масивів (брутфорс, нуль передобробки):

|---|---|

| Двійковий пошук (масиви) | [algo-binary-search](https://github.com/MarynaShavlak/algo-binary-search) |
| Інтерполяційний пошук (масиви) | [algo-interpolation-search](https://github.com/MarynaShavlak/algo-interpolation-search) |
| Індексно-послідовний пошук (масиви) | [algo-indexed-sequential-search](https://github.com/MarynaShavlak/algo-indexed-sequential-search) |
| Бульбашкове сортування | [algo-bubble-sort](https://github.com/MarynaShavlak/algo-bubble-sort) |
| Сортування вставками | [algo-insertion-sort](https://github.com/MarynaShavlak/algo-insertion-sort) |
| Сортування вибором | [algo-selection-sort](https://github.com/MarynaShavlak/algo-selection-sort) |
| Швидке сортування | [algo-quick-sort](https://github.com/MarynaShavlak/algo-quick-sort) |
| Сортування злиттям | [algo-merge-sort](https://github.com/MarynaShavlak/algo-merge-sort) |
| Сортування Шелла | [algo-shell-sort](https://github.com/MarynaShavlak/algo-shell-sort) |
| Порозрядне сортування | [algo-radix-sort](https://github.com/MarynaShavlak/algo-radix-sort) |

**Куди далі.** Наївний метод марнує роботу на повторних порівняннях — і саме її прибирають смартніші наступники:

| Алгоритм | Час | Ідея |
|---|---|---|
| **Наївний пошук** | $O(n \cdot m)$ | ковзає шаблоном, на розбіжності зсув на 1, повторні порівняння |
| **Кнута-Морріса-Пратта (KMP)** | $O(n + m)$ | префікс-функція: на розбіжності зсуває шаблон одразу на кілька позицій, не повторюючи звірених символів |
| **Боєра-Мура** | $O(n / m)$ у найкращому | звіряє з кінця шаблону, евристики «поганого символу» та «доброго суфікса» — великі стрибки |
| **Рабіна-Карпа** | $O(n + m)$ у середньому | хеш ковзного вікна: порівнює спершу хеші, а символи — лише при збігу хешів |

## 21. Підсумок

- **Наївний пошук** ковзає шаблоном уздовж тексту й на кожному вирівнюванні звіряє символи зліва направо; на розбіжності зсуває шаблон на 1 і починає звірку з `j = 0`; на повному збігу повертає позицію, інакше — `-1`.
- **Два індекси:** зовнішній `i` — зміщення вирівнювання (зовнішній `for`), внутрішній `j` — позиція в шаблоні (внутрішній `while`).
- **Нова предметна область — рядки:** дані це текст + шаблон (послідовності символів), операція — посимвольна рівність `==`; нічого не сортується й передумов немає.
- **Марна робота — визначальна риса:** після часткового збігу й розбіжності метод викидає все й зсувається лише на 1, **повторно** порівнюючи вже звірені символи. Саме це прибирають KMP/Боєра-Мура.
- **Складність:** $O(n \cdot m)$, у найгіршому випадку ($m \approx n$) — $O(n^2)$; у найкращому — $\approx n - m + 1$. На канонічному прикладі пошук коштує **29** порівнянь (збіг на позиції 10), а патологічний `AAAAAAAAAA` / `AAAAB` — рівно $(N-M+1)\cdot M = 30$.
- **Достатній** для коротких текстів і рідкісних збігів; для довгих рядків поступається KMP, Боєра-Мура, Рабіна-Карпа.
- Це **перший рядковий алгоритм** у серії — прямий аналог лінійного пошуку для масивів, що відкриває підсерію пошуку в рядках.
