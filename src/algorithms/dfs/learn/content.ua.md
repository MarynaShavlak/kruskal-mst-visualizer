# Пошук у глибину (DFS)

**Обхід графа** — фундаментальний процес: відвідати всі вершини, виконуючи певну дію для
кожної. Пошук у глибину (DFS, *Depth-First Search*) занурюється **якомога глибше** однією
гілкою, доки не впреться в «глухий кут», після чого **повертається назад** (backtrack) і
шукає ще не відвідані вершини. Це друга базова стратегія обходу поряд із BFS.

## 1. Ідея

DFS відвідує вершину, а потім рекурсивно відвідує **першого ще не відвіданого сусіда**,
заглиблюючись усе далі. Коли сусідів не лишилось — повертається на крок назад. Щоб дотриматися
такого порядку «останній прийшов — перший вийшов», потрібен **стек** (LIFO) — явний або через
системний стек рекурсії.

## 2. Рекурсивна реалізація

Найприродніший запис DFS — рекурсія: функція викликає сама себе для кожного невідвіданого
сусіда.

```python {7}
def dfs_recursive(graph, vertex, visited=None):
    if visited is None:
        visited = set()
    visit(vertex)                      # відвідуємо вершину
    visited.add(vertex)
    for x in neighbors(vertex):
        if x not in visited:           # запобігає циклу
            dfs_recursive(graph, x, visited)
```

Перевірка `if x not in visited` обов'язкова: на **циклічному** графі без неї рекурсія була б
нескінченною.

## 3. Ітеративна реалізація

Ту саму логіку можна записати циклом зі **стеком** замість рекурсії:

```python {5,11}
def dfs_iterative(graph, start):
    visited = set()
    stack = [start]                    # фронтир — стек (LIFO)
    while stack:
        v = stack.pop()                # знімаємо з КІНЦЯ
        if v not in visited:
            visit(v)                   # відвідуємо вершину
            visited.add(v)
            for x in reversed(neighbors(v)):  # сусідів — у стек
                if x not in visited:
                    stack.append(x)
```

Сусідів кладемо у **зворотному** порядку, щоб лексикографічно менший сусід опинився зверху
стека й оброблявся першим — так ітеративний DFS дає той самий порядок, що й рекурсивний.

## 4. Приклад покроково

```python
graph = {
    'A': ['B', 'C'],
    'B': ['A', 'D', 'E'],
    'C': ['A', 'F'],
    'D': ['B'],
    'E': ['B', 'F'],
    'F': ['C', 'E'],
}
```

DFS зі старту `A`:

1. Відвідуємо `A`, ідемо до сусіда `B`.
2. З `B` — углиб до `D` (глухий кут), повертаємось, далі `E`.
3. З `E` — до `F`, з `F` — до `C`.
4. Усі вершини відвідані.

Порядок відвідування: **A B D E F C** — спершу одна гілка до кінця, потім backtrack.

## 5. Застосування DFS

- **Перевірка зв'язності**: запускаємо обхід з будь-якої вершини; якщо відвідані всі — граф
  зв'язний.
- **Виявлення циклів**: якщо під час обходу натрапляємо на вже відвідану вершину (не батька) —
  у графі є цикл.
- Основа складніших алгоритмів: топологічне сортування, пошук компонент сильної зв'язності,
  розв'язування лабіринтів.

## 6. Складність

- **Час** — `O(V + E)`: кожну вершину відвідуємо раз, кожне ребро оглядаємо.
- **Пам'ять** — `O(V)`: глибина рекурсії (стек) у найгіршому разі — уся довжина шляху.

## 7. DFS проти BFS

DFS іде «вглиб», BFS — «вшир». DFS економніший за пам'яттю й зручний для задач «чи існує
шлях / цикл / компонента». Та для **найкоротшого** шляху в незваженому графі краще BFS: DFS
може знайти довший маршрут раніше за коротший.

Покрокове порівняння на одному графі — ліворуч BFS, праворуч DFS. Видно, як DFS витягується
в «довгу гілку», а BFS зафарбовує вершини «кущем» (рівнями):

## 8. Різні випадки

### Ланцюг — стратегії збігаються

Якщо граф — проста лінія без розгалужень, DFS і BFS дають **той самий** порядок: просто йдемо
вздовж ланцюга. Різниця між ними виникає лише там, де є вибір сусідів.

![DFS на графі-ланцюгу](trav-chain.svg)

### Циклічний граф — рятує множина «відвіданих»

На циклі DFS міг би кружляти нескінченно. Множина `visited` запобігає цьому: повторну вершину
просто пропускаємо. Саме так DFS і виявляє цикли — натрапивши на вже відвідану вершину.

![DFS на циклічному графі](trav-cyclic.svg)

### Незв'язний граф — корнер-кейс

Обхід з однієї вершини досягає лише її **компоненти зв'язності**. Якщо після завершення
відвідані не всі вершини — граф незв'язний (саме так перевіряють зв'язність обходом).

![DFS на незв'язному графі](trav-disconnected.svg)
