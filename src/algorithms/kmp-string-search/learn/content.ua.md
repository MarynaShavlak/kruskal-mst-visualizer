# Алгоритм Кнута-Морріса-Пратта (KMP): покроковий розбір

**Алгоритм Кнута-Морріса-Пратта (KMP)** — ефективний алгоритм пошуку підрядка в рядку, що працює за **лінійний час** $O(n+m)$. Він розв'язує ту саму задачу, що й [наївний пошук](https://github.com/MarynaShavlak/algo-naive-string-search): знайти, з якої позиції **шаблон** входить у **головний рядок** (текст). Але робить це розумніше.

Наївний метод після розбіжності зсуває шаблон на **одну** позицію й **повторно** порівнює вже звірені символи (індекс тексту при цьому може «відкочуватися» назад). KMP цього не робить: він спершу **один раз** аналізує сам шаблон і будує **префіксну функцію** — таблицю `lps` (*longest prefix suffix*), яка на кожній розбіжності підказує, на скільки «відкотити» індекс шаблону `j`, **не торкаючись тексту**. Завдяки цьому індекс тексту `i` **ніколи не зменшується**.

Алгоритм складається з **двох фаз**:

1. **Передобробка** — `compute_lps(pattern)` будує таблицю `lps` із самого шаблону за $O(m)$, не дивлячись на текст. Це новий, окремий герой розбору, якого не було в наївному методі.
2. **Пошук** — `kmp_search(text, pattern)` робить **один прохід** тексту за $O(n)$, використовуючи `lps` для розумних стрибків шаблону.

Репозиторій — навчальний матеріал: чиста реалізація алгоритму (дослівно з конспекту) + докладні візуалізації кожного кроку обох фаз. Увесь розбір нижче відтворюється кодом із [`examples/`](examples), а рисунки лежать у [`docs/images/`](docs/images).

## 3. Інтуїція: чому повторні порівняння марні

Уявімо, що шукаємо шаблон `ABABCABAB` у тексті й уже звірили **префікс** `ABAB`, а на наступному символі сталася розбіжність. Наївний метод тут зсунув би шаблон на одну позицію й почав звірку **з нуля**, знову порівнюючи символи, які ми вже бачили. Це марна робота.

KMP помічає головне: ми вже **знаємо** звірений шматок тексту — це початок шаблону `ABAB`. А чи має `ABAB` власний **префікс, що водночас є його суфіксом**? Так: `AB` (на початку) дорівнює `AB` (у кінці). Отже, замість починати з нуля, можна зсунути шаблон так, щоб цей `AB`-префікс ліг на свій `AB`-суфікс, і продовжити порівняння далі — **не перечитуючи текст**.

![Ідея KMP: не перечитувати вже звірений префікс](docs/images/intuition.png)

Щоб робити такі стрибки миттєво, KMP заздалегідь рахує для шаблону **таблицю `lps`** — для кожної позиції зберігає довжину найбільшого префікса-суфікса. Це і є передобробка.

## 4. Дві фази KMP

| Фаза | Функція | Що робить | Складність |
|---|---|---|---|
| **1. Передобробка** | `compute_lps(pattern)` | будує таблицю `lps` із самого шаблону (текст не потрібен) | $O(m)$ |
| **2. Пошук** | `kmp_search(text, pattern)` | один прохід тексту з використанням `lps` | $O(n)$ |

Разом — $O(n+m)$, лінійно. Нижче розберемо кожну фазу окремо.

## 5. Фаза 1 — префіксна функція (таблиця `lps`)

### Що таке `lps`: префікс = суфікс

`lps[i]` — це довжина найбільшого **власного** префікса відрізка `pattern[0..i]`, який **одночасно є його суфіксом** (власний — означає не дорівнює всьому відрізку). Таблиця вказує, на скільки «відкотити» індекс шаблону `j` у разі розбіжності під час пошуку, щоб не повертатися до початку шаблону.

### Код `compute_lps` (з конспекту)

Ось реалізація з конспекту — її ми й розбираємо рядок за рядком (повна версія з документацією — у [`knuth_morris_pratt_search/core.py`](knuth_morris_pratt_search/core.py)):

```python
def compute_lps(pattern):
    lps = [0] * len(pattern)
    length = 0
    i = 1
    while i < len(pattern):
        if pattern[i] == pattern[length]:
            length += 1
            lps[i] = length
            i += 1
        else:
            if length != 0:
                length = lps[length - 1]
            else:
                lps[i] = 0
                i += 1
    return lps
```

Алгоритм побудови `lps` (з конспекту):

1. Ініціалізувати довжину найбільшого префікса як `0` (`length = 0`). Почати ітерацію з індексу `1` (бо `lps[0] = 0` завжди: один символ не має власного префікса-суфікса).
2. Порівняти символ на поточній позиції `i` із символом на позиції `length`.
3. Якщо вони **збігаються** — збільшити `length` на 1 і встановити `lps[i] = length`.
4. Якщо **не збігаються** і `length != 0` — встановити `length = lps[length - 1]` (відкотити й перевірити знову, **не просуваючи `i`** — це й уникає зайвих перевірок).
5. Якщо `length == 0` — власного префікса-суфікса немає: встановити `lps[i] = 0` і перейти до наступного індексу.

### Таблиця `lps` для `ABAB`

Розгляньмо шаблон `ABAB`. Друкує таблицю приклад [`examples/01_lps.py`](examples/01_lps.py):

```text
Шаблон «ABAB»: lps = [0, 0, 1, 2]
Індекс:  0   1   2   3
Символ:  A   B   A   B
lps   :  0   0   1   2
```

![Таблиця lps для ABAB: префікс = суфікс](docs/images/lps_table_ABAB.png)

Пояснення кожної позиції:
- **індекс 0** (`A`): найбільший префікс, що є суфіксом, — це сам `A`, але він дорівнює всьому відрізку, тож `lps[0] = 0`;
- **індекс 1** (`AB`): `B` не дає префікса, який був би суфіксом, тому `lps[1] = 0`;
- **індекс 2** (`ABA`): тут `A` є **і префіксом, і суфіксом**, тож `lps[2] = 1`;
- **індекс 3** (`ABAB`): `AB` є **і префіксом, і суфіксом**, отже `lps[3] = 2`.

### Покрокова побудова `AABAA` і крок відкоту

Закріпимо матеріал на шаблоні `AABAA` — він показує найцікавіший крок: **відкіт** `length = lps[length-1]`. Повне трасування друкує [`examples/01_lps.py`](examples/01_lps.py):

```text
Шаблон «AABAA»: lps = [0, 1, 0, 1, 2]
Індекс:  0   1   2   3   4
Символ:  A   A   B   A   A
lps   :  0   1   0   1   2

Покрокова побудова таблиці lps для «AABAA»
  i=1: збіг «A» → length=1, lps[1]=1
  i=2: розбіжність, відкіт length = lps[0] = 0
  i=2: розбіжність при length=0 → lps[2]=0
  i=3: збіг «A» → length=1, lps[3]=1
  i=4: збіг «A» → length=2, lps[4]=2
```

Ключовий момент — **індекс 2**. Символ `B` не збігся з `pattern[length]` (де `length = 1`, тобто `A`). Оскільки `length != 0`, ми не записуємо одразу `0`, а спершу **відкочуємо** `length = lps[length-1] = lps[0] = 0` і перевіряємо знову — **без просування `i`**. Тепер `length = 0`, і вже тоді записуємо `lps[2] = 0`. Саме цей відкіт дозволяє пізніше «зрізати кути» й у фазі пошуку.

## 6. Фаза 2 — пошук

### Код `kmp_search` (з конспекту)

```python
def kmp_search(main_string, pattern):
    M = len(pattern)
    N = len(main_string)
    lps = compute_lps(pattern)
    i = j = 0
    while i < N:
        if pattern[j] == main_string[i]:
            i += 1
            j += 1
        elif j != 0:
            j = lps[j - 1]
        else:
            i += 1
        if j == M:
            return i - j
    return -1  # якщо підрядок не знайдено
```

Логіка пошуку (з конспекту): порівнюємо `pattern[j]` і `main_string[i]`:
- **збіг** → просуваємо обидва індекси (`i += 1`, `j += 1`);
- **розбіжність** і `j != 0` → відкочуємо **лише шаблон** (`j = lps[j - 1]`), а індекс тексту `i` **лишаємо на місці** — це стрибок шаблону вперед на `j - lps[j-1]` позицій;
- **розбіжність** і `j == 0` → просуваємо `i` (шаблон порівнюємо з початку);
- коли `j == M` — усі символи шаблону збіглися, повертаємо позицію початку `i - j`;
- якщо прохід завершився — повертаємо `-1`.

### Приклад із конспекту: пошук «алг» → 4

Відтворимо головний приклад конспекту. Шаблон і текст — **дані** (лишаються кирилицею в обох мовах):

```python
raw = "Цей алгоритм часто використовується в текстових редакторах та системах пошуку для ефективного знаходження підрядка в тексті."

```


```text

   0 |  0 |   Ц  |  а  | зсув i (j=0)
   1 |  0 |   е  |  а  | зсув i (j=0)
   2 |  0 |   й  |  а  | зсув i (j=0)
   3 |  0 |   ␣  |  а  | зсув i (j=0)
   4 |  0 |   а  |  а  | збіг (i+1, j+1)
   5 |  1 |   л  |  л  | збіг (i+1, j+1)
```

### `i` ніколи не відкочується: стрибок за `lps`

Ось де KMP розкривається. Візьмімо канонічний приклад наївного розбору: шукаємо `ABABCABAB` у `ABABDABACDABABCABAB`. Уже звіривши префікс `ABAB`, на символі `D` (позиція 4) стається розбіжність. Наївний метод тут зсунув би шаблон на 1 і почав із нуля. KMP натомість робить `j = lps[3] = 2`: шаблон **перестрибує вперед на 2**, уже звірений зелений «бордюр» `AB` лягає на свій суфікс, а індекс тексту `i` **лишається на місці** (жоден символ не перечитується):

![Стрибок шаблону: i на місці, зелений бордюр зберігається](docs/images/i_monotonic.png)

Саме тому індекс тексту `i` у KMP **монотонно зростає**, тоді як у наївного методу позиція звірки `i+j` «відкочується» назад після кожної розбіжності («пилка» на графіку вище).

## 7. KMP проти наївного методу

### Кількість порівнянь

Звіримо кількість посимвольних порівнянь на тих самих входах (друкує [`examples/03_vs_naive.py`](examples/03_vs_naive.py)):

```text
Вхід: текст «ABABDABACDABABCABAB», шаблон «ABABCABAB»
  наївний: 29 порівнянь
  KMP: 32 порівнянь (lps 9 + пошук 23)
  пошук KMP читає менше символів тексту: 23 проти 29 (а перечитувань — 0)
```

Чесно: на такому **короткому** вході KMP **разом** робить навіть трохи більше порівнянь (32 проти 29) — бо префіксна функція коштує 9 порівнянь. Це **одноразова** ціна передобробки. Але сам **пошук** KMP читає менше символів тексту (23 проти 29) і — головне — **жодного не перечитує**.

Справжня різниця видно на **патологічному** випадку, де наївний метод вибухає:

```text
Масштабування патологічного випадку (текст «AAAA…», шаблон «AAA…B», m ≈ n/2):
  n=16: наївний 72 порівнянь, KMP 38 — наївний у 1.9 раза(ів) більше
  n=32: наївний 272 порівнянь, KMP 78 — наївний у 3.5 раза(ів) більше
  n=64: наївний 1056 порівнянь, KMP 158 — наївний у 6.7 раза(ів) більше
  n=128: наївний 4160 порівнянь, KMP 318 — наївний у 13.1 раза(ів) більше
  n=256: наївний 16512 порівнянь, KMP 638 — наївний у 25.9 раза(ів) більше
```

Наївний росте **квадратично** (учетверо за кожне подвоєння `n`), KMP — **лінійно** (удвічі). Розрив зростає необмежено.

![Наївний проти KMP: найгірший випадок](docs/images/vs_naive_worst.png)

### Складність: `O(n+m)` проти `O(n·m)`

| Метод | Час (гірший) | Перечитування тексту | Передобробка |
|---|---|---|---|
| **Наївний** | $O(n \cdot m)$ → $O(n^2)$ при $m \approx n$ | так (індекс «відкочується») | немає |
| **KMP** | $O(n + m)$ (лінійний) | **ніколи** (індекс `i` лише зростає) | `lps` за $O(m)$ |

![Графік: O(n+m) проти O(n·m)/O(n²)](docs/images/complexity.png)

Лінійність KMP досягається саме завдяки префіксній функції, що уникає зайвих порівнянь у головному рядку.

## 10. Властивості та крайові випадки

- **Складність:** $O(n+m)$ за часом (передобробка $O(m)$ + пошук $O(n)$), $O(m)$ додаткової пам'яті під таблицю `lps`.
- **Індекс тексту `i` ніколи не зменшується** — визначальна перевага над наївним методом: жоден символ тексту не перечитується.
- **Передобробка не залежить від тексту:** одну й ту саму таблицю `lps` можна побудувати раз і шукати шаблон у багатьох текстах.

Крайові випадки (перевірені в [`tests/`](tests)):

| Випадок | Поведінка |
|---|---|
| шаблон **дорівнює** тексту | позиція `0` |
| шаблон **довший** за текст | `-1` (`j` ніколи не дійде до `M`) |
| шаблон з **одного символу** | звичайний пошук |
| **порожній** шаблон | дослівний `kmp_search` дасть `IndexError` (бо `pattern[0]` на порожньому шаблоні)! Безпечну обробку (`0`) дають `kmp_search_all` і `kmp_search_steps` |
| **множинні** входження | `kmp_search` повертає перше; `kmp_search_all` — усі (зокрема перекривні) |

> **Про порожній шаблон.** Код конспекту навмисно збережено **дослівно**, тож на порожньому шаблоні `pattern[j]` (тобто `pattern[0]`) одразу дасть `IndexError`. Це чесна межа дослівної реалізації; навчально-інструментовані версії обробляють її безпечно.

## 11. Місце в серії рядкових алгоритмів

KMP — **другий** рядковий алгоритм серії й **прямий наступник** [наївного пошуку](https://github.com/MarynaShavlak/algo-naive-string-search): він прибирає головну ваду наївного методу — повторні порівняння вже звірених символів. Далі цю ідею розвивають інші алгоритми:

| Алгоритм | Час (гірший) | Передобробка | Ідея |
|---|---|---|---|
| [**Наївний**](https://github.com/MarynaShavlak/algo-naive-string-search) | $O(n \cdot m)$ | немає | зсув на 1, звірка з нуля |
| **KMP** (цей розбір) | $O(n + m)$ | `lps` за $O(m)$ | стрибок за префіксною функцією, `i` не відкочується |
| Боєра-Мура | $O(n \cdot m)$, але швидкий на практиці | таблиці за $O(m + \sigma)$ | порівняння **з кінця**, великі стрибки за «поганим символом» |
| Рабіна-Карпа | $O(n + m)$ у середньому | хеш | ковзний **хеш** замість посимвольного порівняння |

**Ніша KMP** (з конспекту): текстові редактори й системи пошуку — для ефективного знаходження підрядка в тексті, особливо коли важлива гарантована лінійність.

## 12. Підсумок

- **KMP** шукає підрядок за **лінійний час** $O(n+m)$ завдяки **префіксній функції** — таблиці `lps`, яку будують з самого шаблону.
- `lps[i]` — довжина найбільшого власного **префікса**, що є **суфіксом** відрізка `pattern[0..i]`. Еталони: `ABAB → [0,0,1,2]`, `AABAA → [0,1,0,1,2]`.
- **Дві фази:** передобробка `compute_lps` ($O(m)$, не торкається тексту) і пошук `kmp_search` ($O(n)$, один прохід).
- На розбіжності KMP робить `j = lps[j-1]` — **стрибок шаблону вперед** без перечитування тексту; індекс тексту `i` **ніколи не відкочується** (на відміну від наївного методу).
- Проти наївного $O(n\cdot m)$/$O(n^2)$ на патологічних входах KMP лишається лінійним; на тих самих входах робить **істотно менше** посимвольних порівнянь у тексті.
- Приклад конспекту `print(kmp_search(raw, "алг"))` виводить **4**.
