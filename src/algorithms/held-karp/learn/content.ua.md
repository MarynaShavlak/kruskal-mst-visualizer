# Задача комівояжера: повний перебір vs алгоритм Хелда–Карпа

Навчально-дослідницький проєкт, що розв'язує **задачу комівояжера** (Traveling
Salesman Problem) двома **точними** методами й детально порівнює їх на прикладі
п'яти міст:

- **Метод повного перебору** — генерує всі `n!` маршрутів. Простий і гарантовано
  точний, але факторіально повільний — `O(n!)`.
- **Алгоритм Хелда–Карпа** — динамічне програмування з мемоізацією підзадач.
  Той самий точний оптимум, але складність падає до `O(n² · 2ⁿ)`.

Особливий акцент — на **покрокових візуалізаціях**: матриця відстаней, заповнення
таблиці підзадач за рівнями, перевикористання готових блоків і порівняння
складності. Усі рисунки відтворюються кодом із цього репозиторію.

> **Результат прикладу:** обидва методи дають той самий оптимальний маршрут
> **A → C → B → D → E → A** із довжиною ≈ **16.75**.

## 1. Задача комівояжера — метод повного перебору

Комівояжер має відвідати п'ять міст, кожне лише один раз, і повернутися додому.
Мета — знайти найкоротший маршрут. Метод повного перебору генерує **всі** можливі
маршрути та обирає той, де сумарна відстань найменша.

```python
from itertools import permutations
from math import sqrt

# Координати п'яти міст
cities = {"A": (0, 0), "B": (1, 5), "C": (2, 2), "D": (3, 3), "E": (5, 1)}
```

## 2. Відстань між двома містами

Відстань рахуємо за теоремою Піфагора. Якщо місто 1 має координати $(x_1, y_1)$,
а місто 2 — $(x_2, y_2)$, то:

$$ distance = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2} $$

```python
# Відстань між двома містами за їх назвами
def distance(first_city_name, second_city_name):
    x1, y1 = cities[first_city_name]
    x2, y2 = cities[second_city_name]
    return sqrt((x2 - x1) ** 2 + (y2 - y1) ** 2)
```

## 3. Загальна довжина маршруту

Складаємо відстані між усіма сусідніми містами в маршруті
та додаємо зворотний шлях від останнього міста до початкового.

```python
# Загальна відстань маршруту, включно з поверненням у початкову точку
def total_distance_with_return(tour):
    return sum(
        distance(tour[i], tour[i + 1]) for i in range(len(tour) - 1)
    ) + distance(tour[-1], tour[0])
```

## 4. Як працює `total_distance_with_return`

Функція приймає один аргумент — `tour`, тобто послідовність назв міст у тому
порядку, в якому їх відвідують. Наприклад: `('A', 'C', 'B', 'D', 'E')`.

Повертає вона загальну довжину **замкненого** маршруту: усі переїзди між містами
плюс повернення з останнього міста в перше. Вираз складається з двох частин,
які додаються одна до одної.

### Частина 1 — переїзди між сусідніми містами

```python
sum(distance(tour[i], tour[i + 1]) for i in range(len(tour) - 1))
```

- `range(len(tour) - 1)` дає індекси `0, 1, 2, 3` (для 5 міст).
  Чому `- 1`? Бо ми беремо **пари** сусідів `(tour[i], tour[i + 1])`, і для
  останнього міста наступного в списку вже немає — інакше `tour[i + 1]` вийшов би
  за межі та спричинив помилку.
- На кожному кроці `distance(tour[i], tour[i + 1])` рахує відстань між поточним і
  наступним містом. Це **генераторний вираз** — він видає відстані по одній.
- `sum(...)` складає всі ці відстані в одне число.

Для маршруту `('A', 'C', 'B', 'D', 'E')` це переїзди A→C, C→B, B→D, D→E —
тобто 4 відрізки, що з'єднують 5 міст.

### Частина 2 — повернення додому

```python
distance(tour[-1], tour[0])
```

- `tour[-1]` — останнє місто маршруту (`E`). Від'ємний індекс відраховує з кінця.
- `tour[0]` — перше місто, тобто старт (`A`).
- Це відстань зворотного шляху E→A, яка замикає коло.

Без цієї частини ми б порахували лише шлях «туди». Але за умовою задачі комівояжер
має повернутися додому, тому зворотний переїзд обов'язково входить у загальну довжину.

```python
# Розгорнута версія тієї ж логіки — щоб побачити кожен крок окремо.
# Потребує, щоб cities та distance були визначені у попередніх комірках.
tour = ('A', 'C', 'B', 'D', 'E')

total = 0

# Частина 1: переїзди між сусідніми містами
for i in range(len(tour) - 1):
    leg = distance(tour[i], tour[i + 1])
    print(f"{tour[i]} -> {tour[i + 1]}: {leg:.3f}")
    total += leg

# Частина 2: повернення з останнього міста в перше
back = distance(tour[-1], tour[0])
print(f"{tour[-1]} -> {tour[0]}: {back:.3f}  (повернення додому)")
total += back

print(f"\nЗагальна відстань: {total:.3f}")
```

```text
A -> C: 2.828
C -> B: 3.162
B -> D: 2.828
D -> E: 2.828
E -> A: 5.099  (повернення додому)

Загальна відстань: 16.747
```

## 5. Пошук найкоротшого маршруту

`permutations` генерує всі можливі порядки відвідування міст.
Функція `min` обирає маршрут із найменшою загальною відстанню.

```python
# Усі можливі маршрути
all_tours = permutations(cities.keys())

# Маршрут із найменшою загальною відстанню
shortest_tour = min(all_tours, key=total_distance_with_return)

# Довжина цього маршруту з урахуванням зворотного шляху
shortest_distance_with_return = total_distance_with_return(shortest_tour)

print(shortest_tour, shortest_distance_with_return)
```

```text
('A', 'C', 'B', 'D', 'E') 16.746578547999732
```

## 6. Розбір пошуку найкоротшого маршруту крок за кроком

### Крок 1 — згенерувати всі маршрути

```python
all_tours = permutations(cities.keys())
```

- `cities.keys()` повертає назви міст: `'A', 'B', 'C', 'D', 'E'`.
- `permutations(...)` з модуля `itertools` створює **всі можливі порядки**
  відвідування цих міст. Для 5 міст це $5! = 120$ маршрутів.
- Кожен маршрут — це кортеж, наприклад `('A', 'B', 'C', 'D', 'E')`,
  `('A', 'B', 'C', 'E', 'D')` і так далі.
- `permutations` повертає **ітератор** (лінивий, не зберігає всі 120 у пам'яті
  одразу). Важливо: ітератор одноразовий — щойно `min` його пройде, він стане
  порожнім, і повторно перебрати `all_tours` уже не вийде.

### Крок 2 — обрати найкоротший

```python
shortest_tour = min(all_tours, key=total_distance_with_return)
```

Це найважливіший рядок. `min` знаходить найменший елемент, але порівнює маршрути
**не між собою напряму**, а за значенням, яке повертає функція з `key`:

- для кожного маршруту `min` викликає `total_distance_with_return(маршрут)`
  й отримує його довжину (число);
- потім порівнює саме ці числа й залишає маршрут із найменшим.

Зверни увагу: функцію в `key` передаємо **без дужок** —
`key=total_distance_with_return`, а не `...()`. Ми віддаємо саму функцію, а `min`
викликає її стільки разів, скільки треба.

### Крок 3 — дізнатися довжину переможця

```python
shortest_distance_with_return = total_distance_with_return(shortest_tour)
```

`min` повернув лише сам маршрут, а не його довжину. Тому ми викликаємо функцію
ще раз — уже на найкоротшому маршруті — щоб отримати конкретне число.

### Крок 4 — вивести результат

```python
print(shortest_tour, shortest_distance_with_return)
```

Виводить найкоротший маршрут і його довжину:

```
('A', 'C', 'B', 'D', 'E') 16.746578547999732
```

> Зауваження: серед 120 перестановок багато по суті однакових (той самий цикл,
> пройдений у зворотному напрямку чи з іншого старту). Повний перебір не відсіює
> ці повтори — він чесно перевіряє всі 120. Саме тому метод стає надто повільним,
> коли міст багато.

```python
# Що саме перебирає цей код — подивимося наочно.
# Робимо список (не ітератор), щоб пройтись по ньому кілька разів.
all_tours = list(permutations(cities.keys()))

print("Кількість міст:", len(cities))                  # 5
print("Кількість маршрутів (5!):", len(all_tours))     # 120
print()

# Перші 3 маршрути та їх довжини
print("Приклади маршрутів:")
for tour in all_tours[:3]:
    print(" ", tour, "->", round(total_distance_with_return(tour), 3))
print()

# Те, що робить min(..., key=...) "під капотом":
best = None
best_len = None
for tour in all_tours:
    length = total_distance_with_return(tour)
    if best_len is None or length < best_len:
        best = tour
        best_len = length

print("Найкоротший маршрут:", best)
print("Його довжина:", round(best_len, 3))
```

```text
Кількість міст: 5
Кількість маршрутів (5!): 120

Приклади маршрутів:
  ('A', 'B', 'C', 'D', 'E') -> 17.603
  ('A', 'B', 'C', 'E', 'D') -> 18.495
  ('A', 'B', 'D', 'C', 'E') -> 17.603

Найкоротший маршрут: ('A', 'C', 'B', 'D', 'E')
Його довжина: 16.747
```

## 7. Результат

Найкоротший маршрут: **A → C → B → D → E → A**
із загальною відстанню ≈ **16.75** одиниць.

Часова складність методу — факторіальна, $O(n!)$: для 5 міст це 120 перестановок,
а для 10 міст — уже 3 628 800. Тому для великої кількості міст метод стає непрактичним.

## 8. Висновок: часова складність повного перебору

Метод повного перебору **гарантовано знаходить точний оптимальний маршрут**, бо
чесно перевіряє всі можливі варіанти. Але платою за цю точність є
**факторіальна складність $O(n!)$**.

Алгоритм генерує всі перестановки міст ($n!$ штук) і рахує довжину кожної. Тому
кількість обчислень зростає не просто швидко, а вибухоподібно: додавання лише
одного міста множить роботу на нове $n$.

Як це виглядає на числах:

- 5 міст → $5! = 120$ маршрутів (миттєво)
- 10 міст → $10! = 3\,628\,800$ маршрутів (секунди)
- 15 міст → понад $1{,}3$ трлн маршрутів (нереально довго)
- 20 міст → близько $2{,}4 \times 10^{18}$ маршрутів (практично неможливо)

Через це повний перебір придатний лише для **дуже малих задач** — приблизно до
10–12 міст. Для більшої кількості міст потрібні ефективніші підходи: динамічне
програмування (алгоритм Хелда–Карпа, $O(n^2 \cdot 2^n)$) для середніх задач або
евристичні та метаевристичні методи (найближчий сусід, генетичні й мурашині
алгоритми) для великих. Вони не гарантують ідеальний маршрут, зате дають хороший
результат за прийнятний час.

## 9. Задача комівояжера — алгоритм Хелда–Карпа

## 10. Суть методу

Алгоритм Хелда–Карпа розв'язує задачу комівояжера методом **динамічного
програмування**. Замість того щоб перебирати всі $n!$ маршрутів, він розбиває
задачу на підзадачі й повторно використовує їх розв'язки.

Кожна підзадача звучить так: *«який найкоротший шлях, що виходить зі старту,
проходить рівно через задану підмножину міст і закінчується в місті $j$?»*.
Відповіді на ці підзадачі **запам'ятовуються** (мемоізація) і слугують
будівельним матеріалом для більших підмножин.

В основі лежить **оптимальна підструктура**: найкоротший шлях через велику
підмножину міст складається з найкоротших шляхів через менші підмножини плюс
один останній переїзд. Саме це й дозволяє не перераховувати те саме багато разів.

## 11. Покрокова робота

1. **База.** Для кожного міста $i$ запам'ятовуємо відстань зі старту до нього —
   це шлях через підмножину $\{старт, i\}$.
2. **Нарощуємо підмножини** за розміром: спочатку з 3 міст, потім з 4, і так далі.
3. Для кожної підмножини $S$ і кінцевого міста $j$ беремо мінімум за всіма
   можливими передостанніми містами $k$:
   $$ dp[S][j] = \min_{k \in S \setminus \{j\}} \big( dp[S \setminus \{j\}][k] + dist(k, j) \big) $$
4. Коли $S$ містить **усі міста**, ми маємо найкоротші шляхи, що проходять через
   все та закінчуються в кожному місті $j$ (але ще без повернення).
5. **Замикаємо маршрут.** До кожного такого шляху додаємо відстань від його
   останнього міста назад до старту й беремо найменшу суму — це й є оптимальний
   маршрут.

```python
from math import sqrt
from itertools import combinations

# Координати міст (як у методі повного перебору)
cities = {"A": (0, 0), "B": (1, 5), "C": (2, 2), "D": (3, 3), "E": (5, 1)}

# Евклідова відстань між двома точками
def calculate_distance(coord1, coord2):
    return sqrt((coord1[0] - coord2[0]) ** 2 + (coord1[1] - coord2[1]) ** 2)

# Матриця відстаней: distance_matrix[i][j] — відстань від міста i до міста j
distance_matrix = []
for source in cities.values():
    row = [calculate_distance(source, target) for target in cities.values()]
    distance_matrix.append(row)

# Подивимося на матрицю
for row in distance_matrix:
    print([round(d, 2) for d in row])
```

```text
[0.0, 5.1, 2.83, 4.24, 5.1]
[5.1, 0.0, 3.16, 2.83, 5.66]
[2.83, 3.16, 0.0, 1.41, 3.16]
[4.24, 2.83, 1.41, 0.0, 2.83]
[5.1, 5.66, 3.16, 2.83, 0.0]
```

## 12. Що означає матриця відстаней і навіщо вона

Матриця відстаней — це квадратна таблиця розміром $n \times n$ (у нас $5 \times 5$,
бо міст п'ять). У ній **заздалегідь пораховані відстані між усіма парами міст**.

### Що означає кожне число

Число в рядку $i$ і стовпці $j$ — це відстань **від міста $i$ до міста $j$**.
Рядки й стовпці відповідають містам у порядку A, B, C, D, E (індекси 0–4). Кілька
прикладів:

- `distance_matrix[0][1] = 5.10` — відстань від **A до B**;
- `distance_matrix[2][3] = 1.41` — від **C до D** (найближча пара міст);
- `distance_matrix[1][4] = 5.66` — від **B до E** (найдальша пара міст).

Кожне число — це **евклідова (пряма) відстань** між координатами двох міст,
порахована за теоремою Піфагора.

### Дві важливі властивості

- **Нульова діагональ:** `distance_matrix[i][i] = 0` — відстань від міста до
  самого себе дорівнює нулю. Тому по діагоналі стоять нулі.
- **Симетричність:** `distance_matrix[i][j] = distance_matrix[j][i]` — відстань
  від A до B така сама, як від B до A (5.10 в обидва боки). Через це таблиця
  дзеркальна відносно діагоналі.

### Навіщо вона потрібна

Алгоритм Хелда–Карпа всередині своїх циклів **дуже багато разів** звертається до
відстані між парами міст. Якби щоразу рахувати квадратний корінь заново, це було б
повільно й марно. Тому всі відстані обчислюються **один раз наперед** і
складаються в матрицю. Далі алгоритм оперує індексами міст і миттєво бере готове
значення `distance_matrix[i][j]` — швидко й зручно.

## 13. Основний код алгоритму

```python
def held_karp(distance_matrix):
    n = len(distance_matrix)  # кількість міст

    # dp — таблиця динамічного програмування.
    # Ключ: (підмножина міст як frozenset, останнє місто в цій підмножині).
    # Значення: (мінімальна відстань зі старту до цього міста через підмножину,
    #            сам шлях у вигляді списку індексів).

    # --- БАЗА ---
    # Підмножини з двох міст {старт(0), i}: шлях 0 -> i.
    dp = {(frozenset([0, i]), i): (distance_matrix[0][i], [0, i]) for i in range(1, n)}
    # Відстань зі старту до самого себе — 0.
    dp[(frozenset([0]), 0)] = (0, [0])

    # --- НАРОЩУЄМО ПІДМНОЖИНИ за розміром r ---
    for r in range(2, n + 1):
        # Усі підмножини з r міст, обраних серед НЕпочаткових міст (1..n-1)
        for subset in combinations(range(1, n), r):
            subset = frozenset(subset) | frozenset([0])  # додаємо старт

            # Пробуємо зробити кожне місто підмножини кінцевим (next_city)
            for next_city in subset:
                if next_city == 0:
                    continue  # старт не може бути кінцем проміжного шляху

                # Підмножина без кінцевого міста — її розв'язок уже відомий
                prev_subset = subset - frozenset([next_city])

                # Найкоротший шлях у next_city = найкращий варіант серед усіх
                # передостанніх міст last_city з попередньої підмножини.
                dp[(subset, next_city)] = min(
                    (
                        dp[(prev_subset, last_city)][0] + distance_matrix[last_city][next_city],
                        dp[(prev_subset, last_city)][1] + [next_city],
                    )
                    for last_city in prev_subset
                    if last_city != 0
                )

    # --- ЗАМИКАЄМО МАРШРУТ ---
    # До кожного шляху через усі міста додаємо повернення до старту (індекс 0)
    # і беремо мінімум.
    all_cities = frozenset(range(n))
    result = min(
        (
            dp[(all_cities, last_city)][0] + distance_matrix[last_city][0],
            dp[(all_cities, last_city)][1] + [0],
        )
        for last_city in range(1, n)
    )
    return result  # (мінімальна відстань, оптимальний шлях у індексах)
```

## 14. Суть функції `held_karp`

Функція знаходить **точний** найкоротший маршрут методом динамічного
програмування. Її ідея — не перебирати всі $n!$ маршрутів, а розв'язувати
маленькі підзадачі, запам'ятовувати їх і складати з них більші.

### Що зберігає таблиця `dp`

Це словник:

- **Ключ** — пара `(підмножина міст, останнє місто)`. Підмножина — це `frozenset`
  індексів (саме `frozenset`, бо звичайна множина не може бути ключем словника).
- **Значення** — пара `(мінімальна відстань зі старту до цього останнього міста
  через цю підмножину, сам шлях у вигляді списку індексів)`.

Інакше кажучи, `dp[(S, j)]` відповідає на питання: *«який найкоротший шлях, що
виходить зі старту (0), проходить рівно через міста підмножини $S$ і закінчується
в місті $j$?»*.

### Рекурентна формула — серце функції

$$ dp[S][j] = \min_{\substack{k \in S \\ k \ne 0,\, k \ne j}} \big( dp[S \setminus \{j\}][k] + dist(k, j) \big) $$

Словами: щоб дійти до $j$ через підмножину $S$, перебираємо всі варіанти
**передостаннього** міста $k$, беремо вже відомий найкоротший шлях до $k$ (через
$S$ без $j$) і додаємо переїзд $k \to j$. З усіх варіантів лишаємо найдешевший —
це і робить вбудована `min` (як на схемі вище).

Кожен кандидат — це кортеж `(вартість, шлях)`. `min` порівнює кортежі за першим
елементом, тобто за вартістю, тому одразу повертає і найменшу відстань, і
відповідний шлях.

## 15. Чому саме `frozenset`

У таблиці `dp` ключем є пара `(підмножина міст, останнє місто)`, наприклад
`(frozenset([0, 2, 3]), 1)`. Підмножина міст тут — саме `frozenset`, і на це є
дві причини.

### 1. Ключ словника має бути хешованим

Ключі словника (і елементи множини) мають бути **незмінними / хешованими**.
Звичайна множина `set` — **змінна**, тому її не можна хешувати й не можна
використати як ключ: спроба дає `TypeError: unhashable type: 'set'`.
`frozenset` — це «заморожена», незмінна версія множини, і вона **хешована**,
тому спокійно стає ключем словника.

### 2. Потрібна саме множинна семантика (порядок не має значення)

Підмножина міст — це **набір без порядку**: `{A, C, D}` — це та сама підмножина,
хоч як її записати. `frozenset` це забезпечує:
`frozenset([0, 2, 3]) == frozenset([3, 2, 0])` — `True`, і хеш у них однаковий.

Якби замість множини взяли кортеж, то `(0, 2, 3)` і `(3, 2, 0)` були б **різними
ключами**, хоча описують ту саму підмножину. Тоді алгоритм зберігав би купу
дублікатів і втратив би весь сенс мемоізації — повторно використати готовий
розв'язок було б неможливо.

### Бонус: зручні множинні операції

`frozenset` підтримує операції над множинами, які прямо використовує `held_karp`:
- `subset | frozenset([0])` — додати старт до підмножини (об'єднання);
- `subset - frozenset([next_city])` — прибрати кінцеве місто (різниця).

Підсумок: потрібен набір, який **ігнорує порядок**, **прибирає дублікати** і при
цьому **може бути ключем словника** — це рівно те, що дає `frozenset`.

```python
# 1) Звичайна множина НЕ може бути ключем словника
try:
    d = {set([0, 1]): "x"}
except TypeError as e:
    print("set як ключ ->", e)

# 2) frozenset — може
print("frozenset як ключ ->", {frozenset([0, 1]): "ok"})

# 3) Порядок не має значення: та сама підмножина = той самий ключ
a = frozenset([0, 1, 2])
b = frozenset([2, 1, 0])
print("frozenset([0,1,2]) == frozenset([2,1,0]) ->", a == b)
print("однаковий hash ->", hash(a) == hash(b))

# 4) А кортежі трактувались би як РІЗНІ ключі
print("(0,1,2) == (2,1,0) ->", (0, 1, 2) == (2, 1, 0))

# 5) Множинні операції, які використовує held_karp
subset = frozenset([0, 1, 2])
print("subset | {3} ->", subset | frozenset([3]))
print("subset - {1} ->", subset - frozenset([1]))
```

```text
set як ключ -> unhashable type: 'set'
frozenset як ключ -> {frozenset({0, 1}): 'ok'}
frozenset([0,1,2]) == frozenset([2,1,0]) -> True
однаковий hash -> True
(0,1,2) == (2,1,0) -> False
subset | {3} -> frozenset({0, 1, 2, 3})
subset - {1} -> frozenset({0, 2})
```

## 16. Покрокова робота

Функція працює у три фази.

**1. База.** Для кожного міста $i$ записуємо прямий шлях зі старту:
`dp[({0, i}, i)] = (dist(0, i), [0, i])`. Окремо `dp[({0}, 0)] = (0, [0])` —
старт сам до себе, відстань 0.

**2. Нарощування.** Зовнішній цикл `for r` бере підмножини дедалі більшого
розміру — спочатку з 3 міст, потім з 4, і так далі. Для кожної підмножини $S$ і
кожного можливого кінцевого міста `next_city` застосовуємо рекурентну формулу:
дивимося на меншу підмножину `prev_subset = S \ {next_city}` (її розв'язки **вже
пораховані** на попередньому рівні!) і вибираємо найкращого попередника.
Ключове — ми ніколи не рахуємо те саме двічі.

**3. Замикання.** Коли $S$ містить усі міста, маємо найкоротші шляхи, що
закінчуються в кожному місті, але **без повернення додому**. Остання `min` додає
до кожного відстань назад до старту `dist(last, 0)` і вибирає найменшу суму — це
й є оптимальний маршрут.

Комірка нижче запускає ту саму логіку, але **друкує, як заповнюється `dp`** на
кожному рівні — так покрокову роботу видно з реальними числами.

## 18. Як працює `held_karp` — крок за кроком

Алгоритм рахує задачу «знизу вгору»: від найменших підзадач до повного маршруту.
Головне правило одне — кожне нове значення = **готовий блок рівнем нижче + один
переїзд**, а з кількох варіантів береться найменший.

- **База (рівень 2).** Найменша підзадача — дійти з A до одного міста. Думати
  нема над чим: найкоротший шлях — це сам прямий переїзд. Ці значення стають
  фундаментом.
- **Рівень 3.** Якщо в маршруті три міста й він кінчається, скажімо, в B, то перед
  B залишається лише одне можливе місто. Варіант єдиний. Для кожної трійки
  зберігаємо найкращий шлях для *кожного* кінцевого міста — наперед не знаємо,
  який згодиться.
- **Рівень 4 — ключовий момент.** Щойно міст стає чотири, перед кінцевим містом
  можуть стояти вже двоє кандидатів. Тут вмикається `min`: пробуємо прийти з
  кожного (беручи вже пораховану відповідь для меншої підмножини) і лишаємо
  дешевший. Менші шляхи **не перераховуються** — у цьому вся економія.
- **Рівень 5.** Та сама логіка, лише кандидатів троє.
- **Замикання.** Після рівня 5 маємо найкоротші шляхи через усі міста, але це
  «дорога в один кінець». Додаємо повернення в A й беремо найменшу суму. Кілька
  варіантів дають однакові 16.75 — це той самий цикл у різні боки.
- **Результат:** A → C → B → D → E → A, довжина ≈ 16.75 — той самий оптимум, що й
  у повного перебору.

## 19. Покрокова візуалізація: усі підзадачі за рівнями

Нижче кожен рівень показано **повністю** — усі підмножини потрібного розміру й **усі можливі кінцеві міста**, у тому ж порядку, що й текстове трасування `held_karp_traced` вище.

Кожна панель — це оптимальний шлях, що **стартує в A**, відвідує **саме цю підмножину** міст і **закінчується у вказаному місті**. Колір шляху відповідає кінцевому місту (B — бурштиновий, C — синій, D — зелений, E — червоний). Бліді кружечки — міста, яких у цій підмножині немає.

## 20. Як зрозуміти, який шлях обирається

Спершу про сітку рівня 3, бо вона збиває з пантелику. Її 12 панелей — це **6 різних підмножин × 2 кінці = 12 окремих підзадач**, а не 4 групи конкурентів. Якщо згрупувати за кінцевим містом, справді виходить по 3 панелі на кожен кінець — напр. для кінця **B**:

- `{A, B, C}` → B
- `{A, B, D}` → B
- `{A, B, E}` → B

Але ці три **відвідують різні набори міст** — це різні підзадачі, а не варіанти однієї. Алгоритм **зберігає їх усі**: кожна знадобиться як готовий блок на рівні 4. Тут ніхто ні з ким не змагається, тож і обирати нема з чого.

**Де ж тоді вибір?** Він відбувається всередині **однієї** підзадачі — коли в кінець можна прийти з кількох різних передостанніх міст:

- **Рівні 2 і 3 — вибору немає.** Для 3 міст (A + проміжне + кінець) передостаннє місто єдине: напр. `{A, B, C}` кінець B → передостаннім може бути лише C → шлях єдиний `A → C → B`.
- **Рівень 4 — 2 варіанти передостаннього**, рівень 5 — **3**. Ось де алгоритм реально обирає той варіант, де сума **(оптимальний шлях до передостаннього) + (ребро до кінця)** найменша:

$$ dp[S][j] = \min_{k}\big( dp[S \setminus \{j\}][k] + dist(k, j) \big) $$

## 21. Рівні 2–5 і замикання як кольорові таблиці — звідки беруться блоки

Тут видно **повторне використання** готових результатів — суть динамічного програмування. Кожній підмножині дано свій **колір**, а кожній комірці — координату. Щоб не плутати рівні, координати різні: **рівень 2 — `1T…4T`**, **рівень 3 — `1X…4Z`**, **рівень 4 — `5P…8R`**, **рівень 5 — `9M…10N`**; плашки в кандидатах посилаються на ці координати.

- **Рівень 2 (база)** — 4 комірки: пряме ребро `A → X` для кожного міста. Вибору ще немає — це відправна точка. Колір = **кінцеве місто** (бо підмножини-джерела тут ще немає), у кутку — координата `1T…4T`.
- **Рівень 3** — 12 комірок (6 підмножин × 2 кінці). Колір комірки = її підмножина; обидва кінці однієї підмножини мають однаковий колір.
- **Рівень 4** — колір комірки = підмножина-**джерело** `S \ {кінець}`, чиї блоки тут підставляються. **Той самий колір, що в рівні 3** → видно, звідки взято готовий шлях. У заголовку: у наборі `{A, B, C, D}` літери джерела пофарбовано його кольором, а **кінцеве місто — жирним**. Нижче — **обидва кандидати**, кожен окремим рядком: `(A→C→B)` 〔плашка 1X〕 ` = 5.99(2.83+3.16) + 2.83 = 8.82`. **Зелений рядок з ✓ — обраний**, **червоний — відкинутий**. Плашка `1X` — це комірка рівня 3, з якої взято готовий блок. У кутку — власна координата комірки (`5P…8R`).
- **Рівень 5** — 4 комірки (кінці B, C, D, E; координати `9M…10N`). Колір = підмножина-джерело вже з **4 міст**, а **3 кандидати** (бо передостаннім може бути 3 різні міста) посилаються плашками на комірки **рівня 4** (`5P…8R`), пофарбовані під колір тих комірок. Зелений — обраний, червоні — відкинуті. Так само: кольоровий блок на малюнку — готовий шлях рівня 4, коралове ребро — нове, останнє перед поверненням.
- **Замикання** — 4 комірки (по одній на кінець). Беремо готовий шлях рівня 5 (плашка `9M…10N`) і додаємо ребро `j → A`, щоб закільцювати маршрут: `тур = (вартість рівня 5) + (ребро назад)`. Колір комірки збігається з кольором відповідної комірки рівня 5. Тут вибір **між** комірками: `✓` — ті кінці, що дають **мінімальний тур** (16.75). Кольоровий блок — шлях рівня 5, коралове ребро — повернення в A.

Приклад: комірка `{A, B, C, D} → B` (помаранчева) бере помаранчевий блок `{A, C, D}` з рівня 3 і порівнює два варіанти: через C (`5.66 + 3.16 = 8.82`, червоний) і через D (`4.24 + 2.83 = 7.07`, зелений ✓) — обирає D.

### ⬇️ Рівень 2 у коді — це блок **`--- БАЗА ---`**

Саме цей фрагмент `held_karp` створює те, що показано в таблиці нижче (прямі ребра `A → X`):

```python
# --- БАЗА ---
dp = {(frozenset([0, i]), i): (distance_matrix[0][i], [0, i]) for i in range(1, n)}
dp[(frozenset([0]), 0)] = (0, [0])
```

Кожен запис `dp[(frozenset([0, i]), i)]` — одна комірка цієї таблиці: підмножина `{0, i}` (старт + місто `i`), кінець `i`, вартість = `distance_matrix[0][i]`, шлях = `[0, i]`. Вибору тут ще немає — це відправні значення.

![Рівень 2 (база) — прямі ребра A→X для кожного міста.](images/03_level2_base.png)

*Рівень 2 (база) — прямі ребра A→X для кожного міста.*

### ⬇️ Рівень 3 у коді — **перший прохід** циклу нарощування, `r = 2`

```python
for r in range(2, n + 1):                 # r = 2  →  підмножини з 3 міст
    for subset in combinations(range(1, n), r):
        subset = frozenset(subset) | frozenset([0])
        for next_city in subset:
            if next_city == 0:
                continue
            prev_subset = subset - frozenset([next_city])
            dp[(subset, next_city)] = min(
                (
                    dp[(prev_subset, last_city)][0] + distance_matrix[last_city][next_city],
                    dp[(prev_subset, last_city)][1] + [next_city],
                )
                for last_city in prev_subset
                if last_city != 0
            )
```

При `r = 2` цикл бере підмножини з **3 міст**. У кожній комірці `min(...)` пробує всі передостанні міста `last_city`, бере готовий блок `dp[(prev_subset, last_city)]` (це рівень 2) і додає ребро `last_city → next_city`. Тут `prev_subset` має лише 2 міста `{0, last_city}`, тож кандидат **єдиний** — справжнього вибору ще немає.

### ⬇️ Рівень 4 у коді — **той самий цикл**, наступний прохід `r = 3`

Це **той самий рядок `dp[(subset, next_city)] = min(...)`**, просто наступне значення `r`:

```python

        if last_city != 0
    )
```

При `r = 3` підмножини вже з **4 міст**, а `prev_subset` — це готові блоки **рівня 3** (вони вже лежать у `dp`). Тепер `prev_subset` має 3 міста, отже `min(...)` обирає серед **кількох** `last_city` — звідси й зелений (обраний) проти червоних (відкинутих) рядків у таблиці.

## 22. Рівень 4. Пояснення першої клітинки (помаранчева 5Р): чому min(8.82, 7.07) = 7.07 і маршрут A → C → D → B

Ми будуємо найкоротший шлях, що відвідує **{A, B, C, D}** і **закінчується в B**.
Місто прямо перед B (його «попередник») може бути лише C або D — звідси два варіанти.

**Варіант «через C»** (C стоїть перед B):
- беремо вже готовий блок «найкоротший шлях через {A, C, D}, що кінчається в C» —
  це A → D → C, довжина 5.66 (порахований на рівні 3);
- додаємо переїзд C → B = 3.16;
- разом: 5.66 + 3.16 = **8.82**, маршрут A → D → C → B.

**Варіант «через D»** (D стоїть перед B):
- беремо готовий блок «найкоротший шлях через {A, C, D}, що кінчається в D» —
  це A → C → D, довжина 4.24;
- додаємо переїзд D → B = 2.83;
- разом: 4.24 + 2.83 = **7.07**, маршрут A → C → D → B.

Оскільки 7.07 < 8.82, перемагає «через D».

### Звідки в маршруті взялося C перед D?

Це і є ключовий момент. Коли ми кажемо «через D», ми **не вирішуємо окремо**, де
поставити C. Ми просто підставляємо вже готовий найкоротший шлях до D через
{A, C, D} — а він усередині сам має вигляд A → C → D (бо так коротше). Алгоритм не
складає маршрут з нуля: він бере **цілий оптимальний шматок**, порахований
раніше, і додає до нього лише один останній переїзд D → B. Тому й виходить
A → C → D → B.

### ⬇️ Рівень 5 у коді — **той самий цикл**, останній прохід `r = 4`

```python
for r in range(2, n + 1):                 # r = 4  →  підмножина з усіх 5 міст

    )
```

При `r = 4` підмножина — це вже всі **5 міст**, а `prev_subset` — готові блоки **рівня 4**. Виходить 4 комірки (кінці B/C/D/E), і в кожній `min(...)` обирає найдешевший із **3** кандидатів.

## 23. Чому це швидше за перебір: «обчислити раз — використати багато»

Перебір рахує кожен маршрут незалежно, тож **спільні початки** (наприклад `A → C`) сумуються знову й знову. Динамічне програмування рахує кожну підзадачу **один раз** і підставляє готовий результат усюди, де він потрібен. Ось та сама ідея на одному прикладі:

## 24. Складність

- **Час: $O(n^2 \cdot 2^n)$.** Підмножин міст усього $2^n$; для кожної перебираємо
  кінцеве місто ($n$ варіантів), а для кожного — попереднє місто ($n$ варіантів).
- **Пам'ять: $O(n \cdot 2^n)$** — стільки записів зберігається в таблиці `dp`.

Це експоненційно, але **набагато краще за факторіальний** $O(n!)$ повного перебору.
Наприклад, для $n = 20$: повний перебір дає $20! \approx 2.4 \times 10^{18}$ варіантів,
а Хелда–Карпа — лише близько $20^2 \cdot 2^{20} \approx 4 \times 10^8$ операцій,
тобто у мільярди разів менше.

## 25. Значення

Алгоритм Хелда–Карпа (1962) — це **перший точний алгоритм для задачі комівояжера,
що працює суттєво швидше за наївний перебір**, і досі асимптотично найшвидший
відомий точний метод у загальному випадку. Його значення:

- наочно демонструє силу динамічного програмування — мемоізацію та оптимальну
  підструктуру;
- дає **гарантовано оптимальний** маршрут (на відміну від евристик);
- практично застосовний для малих і середніх задач — приблизно до 15–20 міст.

## 26. Висновки

- Хелда–Карпа замінює перебір $n!$ маршрутів на роботу з $2^n$ підмножинами:
  складність падає з $O(n!)$ до $O(n^2 \cdot 2^n)$.
- Працює завдяки тому, що розв'язки менших підзадач зберігаються й повторно
  використовуються для більших — кожен «рівень» спирається на попередній.
- Залишається експоненційним через множник $2^n$, тому для дуже великих наборів
  (сотні міст) стає надто важким за часом і **особливо за пам'яттю**.
- Для великих задач переходять до евристичних і метаевристичних методів
  (найближчий сусід, генетичні, мурашині алгоритми), які жертвують точністю
  заради швидкості.
- На нашому прикладі алгоритм підтвердив той самий оптимум, що й повний перебір:
  **A → C → B → D → E → A** із довжиною ≈ **16.75**.
