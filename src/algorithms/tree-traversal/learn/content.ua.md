# Дерева. Реалізація. Обхід дерева

**Дерево** — ієрархічна структура даних для відношень «один до багатьох». Воно
складається з **вузлів**; кожен вузол може мати кілька **дочірніх**, але лише одного
**батька**. Вершина без батька — **корінь**. На відміну від масиву чи хеш-таблиці,
дерево зберігає не лінійний список, а саме *ієрархію*.

## 1. Будова дерева

Розберемо словник термінів на невеликому дереві:

- **Корінь** — єдиний вузол без батька; звідси починається будь-який обхід.
- **Батьківський вузол** — вузол, що має дочірні.
- **Дочірній вузол (дитина)** — вузол, до якого веде ребро від батька.
- **Лист** — вузол без дітей (кінець гілки).
- **Вузол розгалуження** — вузол, що має хоча б одну дитину.
- **Ребро** — з'єднання між двома вузлами.
- **Братні вузли** — вузли зі спільним батьком.
- **Висота дерева** — число ребер найдовшого шляху від кореня до листа.
- **Предок / нащадок** — вузли, досяжні переходами вгору (до батька) / вниз (до дитини).

## 2. Двійкове (бінарне) дерево

**Двійкове дерево** — дерево, де кожен вузол має **не більше двох** дітей: ліву та
праву. Саме двійкові дерева — основа складніших структур: **дерев двійкового пошуку
(BST)**, **AVL-** та **червоно-чорних дерев**. Базовий вузол описують так:

```python
class Node:
    def __init__(self, key):
        self.left = None      # ліве піддерево
        self.right = None     # праве піддерево
        self.val = key        # значення вузла
```

Далі скрізь працюємо з деревом-прикладом: корінь `1`, його діти `2` і `3`, а у вузла
`2` — діти `4` і `5`.

## 3. Що таке обхід

**Обхід дерева** — це процес відвідування *всіх* вузлів і виконання дії (зазвичай
виводу) над кожним. Головна мета — відвідати кожен вузол **рівно один раз**. Залежно
від *послідовності* відвідування розрізняють кілька способів обходу.

Для двійкового дерева є три класичні обходи **в глибину**. Усі три відвідують кожен
вузол один раз — різниця лише в тому, **коли** ми відвідуємо корінь відносно лівого та
правого піддерев:

| Обхід | Порядок | На прикладі |
|-------|---------|-------------|
| Прямий (preorder) | **корінь** → ліве → праве | 1, 2, 4, 5, 3 |
| Центровий (inorder) | ліве → **корінь** → праве | 4, 2, 5, 1, 3 |
| Зворотний (postorder) | ліве → праве → **корінь** | 4, 5, 2, 3, 1 |

Кожен обхід — це **рекурсія**: функція викликає себе для лівого й правого піддерева.
Базовий випадок — порожня гілка (`None`): рекурсія одразу повертається. Саме стек
викликів функції і породжує порядок відвідування (це видно в плеєрі — панель «стек
рекурсії»).

## 4. Прямий обхід (preorder)

У прямому обході спершу відвідуємо **корінь**, потім рекурсивно — ліве піддерево,
потім праве:

```python {3}
def preorder(node):
    if node:
        print(node.val)        # 1) КОРІНЬ — відвідуємо ПЕРШИМ
        preorder(node.left)    # 2) ліве піддерево
        preorder(node.right)   # 3) праве піддерево
```

На дереві-прикладі це дає `1, 2, 4, 5, 3`. Прокрутіть обхід крок за кроком:

![Прямий обхід крок за кроком](docs/images/tt_preorder.png)

Прямий обхід зручний, коли треба **скопіювати** дерево або **зберегти** його у файл
так, щоб потім легко відновити: корінь іде першим, тож дерево відбудовується згори вниз.

## 5. Центровий обхід (inorder)

У центровому обході спершу йдемо в **ліве** піддерево, потім відвідуємо **корінь**,
і лише потім — **праве**:

```python {4}
def inorder(node):
    if node:
        inorder(node.left)     # 1) ліве піддерево
        print(node.val)        # 2) КОРІНЬ — відвідуємо в СЕРЕДИНІ
        inorder(node.right)    # 3) праве піддерево
```

На дереві-прикладі виходить `4, 2, 5, 1, 3`:

![Центровий обхід крок за кроком](docs/images/tt_inorder.png)

**Головна властивість.** Якщо дерево — це **дерево двійкового пошуку** (BST: ліворуч
менші значення, праворуч більші), то центровий обхід видає значення у **відсортованому
порядку**. Це «нагорода» за структуру пошуку й прямий місток до двійкового пошуку:

![Центровий обхід BST дає відсортовану послідовність](docs/images/tt_bst.png)

## 6. Зворотний обхід (postorder)

У зворотному обході корінь відвідуємо **останнім** — спершу ліве піддерево, потім
праве, і лише тоді сам вузол:

```python {5}
def postorder(node):
    if node:
        postorder(node.left)   # 1) ліве піддерево
        postorder(node.right)  # 2) праве піддерево
        print(node.val)        # 3) КОРІНЬ — відвідуємо ОСТАННІМ
```

На дереві-прикладі це `4, 5, 2, 3, 1`:

![Зворотний обхід крок за кроком](docs/images/tt_postorder.png)

Зворотний обхід обробляє **дітей раніше за батька** — це саме те, що треба, коли
результат для вузла залежить від піддерев. Наприклад, щоб порахувати суму всіх значень
дерева, спершу рахуємо суми лівого й правого піддерев, а потім додаємо значення кореня.
З тієї ж причини так **безпечно видаляють** дерево: спочатку звільняють дітей, потім
батька.

## 7. Навіщо потрібні дерева

Дерева зберігають **ієрархічну** інформацію, яку складно або неможливо подати лінійним
масивом. Приклади всюди:

- **файлова система**: каталоги й підкаталоги;
- **HTML / XML (DOM)**: документ як дерево тегів;
- **синтаксичний аналіз**: дерево розбору арифметичного виразу.

Порівняймо з **хеш-таблицею**. Хеш-таблиця дає доступ за ключем у середньому за O(1),
але **не зберігає порядку** й витрачає пам'ять на розв'язання колізій. Дерево
повільніше (операції в загальному дереві — O(n), у збалансованому дереві пошуку —
O(log n)), проте дає те, чого хеш-таблиця не вміє: **впорядкований обхід** даних і
природне подання ієрархії.

## 8. Складність і місток далі

Будь-який із трьох обходів відвідує кожен вузол рівно один раз, тож його час —
**O(n)**, а додаткова пам'ять — O(h) на стек рекурсії (де h — висота дерева).

Дерево двійкового **пошуку** робить операції пошуку / вставки / видалення
логарифмічними — O(log n) на збалансованому дереві. А **зворотний** обхід, що рахує
відповідь для піддерев *перш ніж* для батька, — це вже сама думка **динамічного
програмування**: складай ціле з готових розв'язків менших частин. Саме туди веде
наступний крок курсу.
