# Пірамідальне сортування (Heap Sort): покроковий розбір

**Пірамідальне сортування** (Heap Sort) — це метод сортування, що використовує структуру даних **купа** (heap, «піраміда»). Ідея проста й елегантна: спершу ми перетворюємо невпорядкований масив на купу, де **найбільший** (або найменший) елемент завжди «спливає» на вершину; далі багаторазово знімаємо цю вершину й ставимо її на своє остаточне місце. На відміну від швидкого сортування, Heap Sort **гарантує** $O(n \cdot \log n)$ у **будь-якому** випадку й працює **на місці** (без додаткової пам'яті).

Цей розбір показує найголовніше наочно: як **масив одночасно є двійковим деревом**, що таке **просіювання** (heapify), як із хаосу постає **купа**, і як відсортований «хвіст» масиву **наростає з кінця**.

## 1. Купа: ідея і два різновиди

**Купа** — це двійкове дерево з двома властивостями:

1. **Повнота форми.** Дерево заповнене за рівнями зліва направо (усі рівні, крім, можливо, останнього, повні). Саме тому його можна щільно зберігати в масиві без «дірок».
2. **Властивість купи.** У **max-купі** кожен **батько ≥ своїх дітей** (на вершині — максимум). У **min-купі** навпаки: кожен **батько ≤ дітей** (на вершині — мінімум).

Зверніть увагу: купа — це **не** відсортований масив. Вона лише гарантує, що **корінь** — екстремум. Брати й сини між собою не впорядковані — і це нормально.

Щоб відсортувати **за зростанням**, ми будуємо **max-купу** (найбільше зверху); щоб **за спаданням** — **min-купу**.

## 2. Масив як двійкове дерево

Ключове прозріння методу: купу **не** треба зберігати окремими вузлами з вказівниками. Повне дерево ідеально лягає в масив за рівнями. Для елемента з індексом `i`:

- **ліва дитина** — на індексі `2i + 1`;
- **права дитина** — на індексі `2i + 2`;
- **батько** — на індексі `(i − 1) // 2`.

Тобто «дерево» — це просто інший спосіб **прочитати той самий масив**. Натисни кроки нижче: у вузлах показано індекси, а під деревом — той самий масив комірками.

![Масив як двійкове дерево: формули індексів](docs/images/heap_index_map.png)

Останній **батьківський** вузол має індекс `n // 2 − 1` — усі індекси після нього є **листками** (дітей не мають). Це межа, з якої почнеться побудова купи.

## 3. Просіювання вниз (heapify)

**Просіювання вниз** (sift-down, його часто й називають `heapify`) — серце алгоритму. Воно «занурює» вузол на його законне місце, відновлюючи властивість купи в одному піддереві:

1. Дивимося на вузол `i` та його дітей.
2. Знаходимо **найсильнішу** з трьох (для max-купи — найбільшу): батька чи когось із дітей.
3. Якщо сильніша — **дитина**, міняємо її з батьком місцями й **повторюємо** просіювання вже з нової позиції (бо обмін міг порушити купу нижче).
4. Якщо батько вже сильніший за обох дітей — усе на місці, зупиняємось.

```python {4,6,8}
def heapify(a, n, i):        # просіюємо вузол i вниз у купі розміру n
    largest = i
    l, r = 2*i + 1, 2*i + 2
    if l < n and a[l] > a[largest]:   # ліва дитина більша?
        largest = l
    if r < n and a[r] > a[largest]:   # права дитина більша?
        largest = r
    if largest != i:                  # батько менший за дитину →
        a[i], a[largest] = a[largest], a[i]   # піднімаємо дитину
        heapify(a, n, largest)        # просіюємо далі вниз
```

Один прохід просіювання робить щонайбільше **висоту дерева** обмінів, тобто $O(\log n)$.

## 4. Алгоритм: дві фази

Пірамідальне сортування складається рівно з двох фаз:

1. **Побудова купи.** Перетворюємо весь масив на max-купу.
2. **Сортування.** Багаторазово знімаємо корінь (максимум) і ставимо його в кінець, зменшуючи купу.

```python {3,4,6,7,8}
def heap_sort(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):   # 1) побудова max-купи
        heapify(a, n, i)
    for end in range(n - 1, 0, -1):       # 2) сортування
        a[0], a[end] = a[end], a[0]       # корінь → у кінець
        heapify(a, end, 0)                # відновлюємо купу меншого розміру
    return a
```

## 5. Фаза 1 — побудова купи

Будувати купу починаємо **не** з кореня, а з **останнього батьківського** вузла (`n // 2 − 1`) і рухаємось **назад до кореня**, просіюючи кожен вузол униз. Чому з кінця? Бо коли ми просіюємо вузол, його піддерева вже мають бути купами — а листки (друга половина масиву) є тривіальними купами «самі по собі».

![Побудова купи: до і після](docs/images/heap_build.png)

Хоч кожне просіювання коштує до $O(\log n)$, акуратний підрахунок показує, що **вся побудова** — лише $O(n)$: більшість вузлів близько до листя й просіюються на 1–2 рівні.

## 6. Фаза 2 — сортування витягуванням

Тепер корінь — гарантовано **найбільший** елемент. Сортуємо так:

1. Міняємо корінь `a[0]` з **останнім** елементом купи. Максимум опиняється на своїй **остаточній** позиції в кінці.
2. **Вилучаємо** цей елемент із купи (зменшуємо її розмір на 1) — він уже відсортований.
3. Просіюємо новий корінь униз, **відновлюючи** купу.
4. Повторюємо, доки в купі не лишиться один елемент.

Відсортована зона **наростає справа наліво**, а купа з кожним кроком стискається. Коли купа спорожніє — масив відсортовано.

## 8. За зростанням і за спаданням

Напрям сортування задає **тип купи**: max-купа → за зростанням, min-купа → за спаданням (у плеєрі це перемикач «Напрям»). Усе інше — той самий алгоритм, лише знак порівняння в `heapify` змінюється з `>` на `<`.

![Порівняння напрямів на тому самому масиві](docs/images/order_compare.png)

У конспекті GoIT той самий результат отримують **без власного `heapify`** — через стандартний модуль `heapq` (він реалізує **min-купу**). Хитрість зі знаком дає обидва напрями:

```python
import heapq

def heap_sort(iterable, descending=False):
    sign = -1 if descending else 1          # знак задає порядок
    h = [sign * el for el in iterable]
    heapq.heapify(h)                         # побудова купи за O(n)
    return [sign * heapq.heappop(h) for _ in range(len(h))]

print(heap_sort([12, 11, 13, 5, 6, 7]))                  # [5, 6, 7, 11, 12, 13]
print(heap_sort([12, 11, 13, 5, 6, 7], descending=True)) # [13, 12, 11, 7, 6, 5]
```

> 💡 `heapq` зручний на практиці, але «навчальна» реалізація з власним `heapify` краще показує, **що саме** відбувається в купі. Саме її візуалізує плеєр.

## 9. Складність

Часова складність складається з двох фаз:

- **Побудова купи** — $O(n)$.
- **Сортування** — $n$ разів витягуємо корінь, кожне відновлення коштує $O(\log n)$, разом $O(n \cdot \log n)$.

Сумарно: $O(n + n\log n) = O(n \cdot \log n)$ — і у **найкращому**, і в **середньому**, і в **найгіршому** випадках.

![Зростання n·log n проти n²](docs/images/growth.png)

Heap Sort **не адаптивний**: на «вже відсортованому» вході він не швидший. Більше того, зростаючий масив — це насправді min-купа, тож max-купу доводиться будувати з нуля (роботи навіть трохи більше, ніж на зворотному вході):

![Та сама ціна на різних входах](docs/images/non_adaptive.png)

## 10. Властивості методу

- **На місці** — потрібно лише $O(1)$ додаткової пам'яті (на відміну від сортування злиттям).
- **Гарантований** $O(n \cdot \log n)$ — немає «злого» входу, що зриває метод у $O(n^2)$ (на відміну від швидкого сортування з невдалим опорним).
- **Нестабільний** — рівні ключі можуть змінити взаємний порядок (далекі обміни в дереві).
- **Не адаптивний** — порядок входу майже не впливає на ціну.

Тому Heap Sort часто обирають там, де важлива **гарантія** найгіршого випадку й **обмежена пам'ять**.

## 12. Підсумок

- Купа — це **повне двійкове дерево в масиві**: діти вузла `i` — на `2i+1` і `2i+2`.
- **Просіювання** (`heapify`) відновлює властивість купи за $O(\log n)$.
- Алгоритм = **побудова max-купи** $O(n)$ + **витягування кореня** $n$ разів по $O(\log n)$.
- Підсумок — **$O(n \cdot \log n)$ завжди**, **на місці**, але **нестабільний** і **не адаптивний**.

Повний код і приклади — у компаньйон-репозиторії з Python-розборами серії сортувань.
